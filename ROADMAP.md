# resticker — дорожная карта

Порядок вех выбран так, чтобы **каждая заканчивалась чем-то запускаемым**, и чтобы самые рискованные технические вещи проверялись как можно раньше, пока не поздно менять архитектуру.

Оценки — для одного разработчика, работающего с помощью Claude, при загрузке порядка 10–15 часов в неделю. Это ориентир, а не обещание. Реальность обычно оказывается в полтора раза дольше.

---

## Спайк S0 — проверка гипотезы (2–4 дня, **до всего остального**)

Самое главное в проекте — маска перекрытия и прозрачное композиционное окно. Если это не работает, вся архитектура другая. Поэтому это делается **первым**, одним грязным прототипом на 300 строк, который потом выбрасывается.

- [x] Win32-окно с `WS_EX_NOREDIRECTIONBITMAP | WS_EX_TOPMOST | WS_EX_TRANSPARENT`
- [x] D3D11 + DirectComposition, swapchain через `CreateSwapChainForComposition` с premultiplied alpha
- [x] Отрисовать один PNG с прозрачностью
- [x] Убедиться, что клики проходят насквозь
- [x] `SetWinEventHook` на `FOREGROUND` + `LOCATIONCHANGE`, вывод прямоугольников окон в консоль
- [x] Вырезать из PNG прямоугольник окна «Блокнот» через маску — и увидеть, что PNG действительно «уходит под» Блокнот
- [x] Замерить CPU при перетаскивании окна по экрану

**Критерий успеха:** картинка честно скрывается под Блокнотом, при перетаскивании окна CPU не превышает 2%.
**Если провалится:** пересматриваем раздел 3 ARCHITECTURE.md. Запасной вариант — `WS_EX_LAYERED` + `UpdateLayeredWindow` (медленнее) или отказ от выборочных слоёв в пользу двух режимов «поверх всего» / «на рабочем столе».

## M5 — анимация и видео (3–5 недель)

Самый непредсказуемый по срокам этап: FFmpeg всегда преподносит сюрпризы.

**M5a — GIF и анимированный WebP (~1 неделя)**
- [x] Декодирование всех кадров в текстурный атлас, анимация через смену UV
- [x] Собственные часы на стикер, планировщик ближайшего дедлайна
- [x] Потоковый режим для очень длинных анимаций (>300 кадров или >256MB,
      `rst_media::animation::MAX_FRAMES`/`MAX_ATLAS_BYTES`): вместо честного
      отказа (`TooManyFrames`/`TooLargeForAtlas`) координатор переключается
      на `rst_media::animation::StreamingAnimation` — декодирует по одному
      кадру за раз (не материализует всю анимацию) в единственную
      переиспользуемую GPU-текстуру (`Device::create_streaming_animation_frame`/
      `update_streaming_animation_frame`, тот же паттерн, что видеокадры).
      Луп — рестарт декодера с начала файла внутри `next_frame()`, часы —
      без модульной арифметики атласного `AnimationClock` (декодирование
      кадра стоит реальных CPU-циклов, поэтому после долгой паузы процесса
      анимация просто продолжает с текущего кадра, а не досчитывает
      пропущенные). `sniff_media_type`/`add_sticker`/`RelinkSticker`
      классифицируют такие файлы как `MediaType::Animation`, а не как
      статику — раньше именно это тихо отключало анимацию для больших
      файлов. Покрыто юнит-тестами декодера (rst-media) и GPU-тестом
      создания/обновления потоковой текстуры (rst-render, `--ignored`,
      проверено на реальном железе).
- [x] APNG

**M5b — видео, программный декод (~1,5 недели)**
- [x] Сборка и линковка FFmpeg (LGPL shared, `--disable-gpl --disable-nonfree`)
- [x] Демуксер, декодер, очередь на 3 кадра, пул потоков
- [x] Луп через `av_seek_frame`
- [x] Конверсия YUV → RGB на GPU в шейдере (не через `sws_scale` на CPU)
- [x] Пауза декодирования для невидимых стикеров (`sticker_should_tick` +

      исправлено независимым ревью сшивки, `0f2b1ec`)

**M5c — аппаратный декод (~1 неделя)**

**M5d — звук (~1 неделя)**

## M6 — стикеры-окна (1–2 недели)

Фича полностью рабочая для основного сценария: «Добавить окно» в панели у
курсора → подсветка окна под курсором → клик закрепляет его
(`WS_EX_TOPMOST` + маркер) как новый стикер-окно, `placement` зеркалит
прямоугольник окна 1:1 на каждое внешнее изменение, а перетаскивание/ресайз
стикера в режиме редактирования двигает/ресайзит настоящее окно назад
(двусторонняя синхронизация). Уничтожение таргета убирает стикер из
активного списка, выход из приложения снимает все закрепления. Поворот и
прозрачность недоступны для стикера-окна на уровне жеста/тулбара — не
просто «эффекта нет», а сама возможность заблокирована (SPEC §5.2).

- [x] Режим выбора окна с подсветкой под курсором (`BTN_ADD_WINDOW` →
      `edit.picking_window`, наведение — `window_pick::window_at` +
      `window_highlight::WindowHighlight`, `Esc`/клик мимо окна отменяет)
- [x] `pin` / `unpin` через `SetWindowPos` + оконное свойство-маркер
      (закрепление — сам таргет получает `WS_EX_TOPMOST`, SPEC.md §5:
      «стикер» — это окно, не отдельный HWND; семантика `window_pin.rs`
      скорректирована под это в процессе интеграции, найден и исправлен
      попутный баг — `unpin` не снимал `WS_EX_TOPMOST`)
- [x] Гарантированное открепление при выходе (`window_pins.unpin_all()` в
      конце `run()`; аварийный выход/`WM_ENDSESSION` не покрыты — код после
      kill/crash не выполняется, известный предел, не путать с багом)
- [x] Перемещение и ресайз в пределах правил окна: двусторонняя
      синхронизация — `sync_window_stickers` зеркалит окно → `placement` на
      внешние изменения, `WindowPins::move_resize` (новый, `SetWindowPos`
      без смены z-order/фокуса) применяет `placement` → окно на каждый шаг
      живого драга/ресайза стикера в `apply_gesture`; Windows сам
      ограничивает итоговый размер минимумом/максимумом окна
- [x] `EVENT_OBJECT_DESTROY` → корректное удаление (`sync_window_stickers`
      скармливает снимки `WindowPins::handle_snapshot`, `TargetDestroyed`
      убирает стикер из `cfg.stickers` и из выделения)
- [x] Обработка UIPI: понятное сообщение про права администратора
      (`Win32Error::PinAccessDenied`, текст с предложением перезапуска от
      администратора — SPEC §5.3), теперь ещё и баллон-уведомлением трея
      (`TrayIcon::show_balloon`, тот же общий канал закрыл заодно и
      `HotkeyConflict` из M2, который раньше уходил только в лог)
- [x] Виртуальные рабочие столы через `IVirtualDesktopManager` с fallback
      (`virtual_desktops::is_window_on_current_desktop` — публичный COM,
      Windows 10 1607+; `MoveWindowToDesktop` сознательно не реализован —
      публичный API не даёт перечислить GUID'ы столов, только
      недокументированные приватные интерфейсы, это и есть fallback, а не
      обход, ROADMAP это и просил). Явно из координатора НЕ вызывается —
      выяснилось, что не нужно: `window_enum.rs` уже отсекает cloaked-окна
      (`DWMWA_CLOAKED`, M4), а DWM кложит окна других виртуальных столов —
      «стикер не отображается, но не теряется» (SPEC §5.3) уже верно само
      по себе через `sync_window_stickers` (окно вне снимка, но `IsWindow`
      живо → `placement` просто не обновляется и не сбрасывается)

Осознанно за скобками первого рабочего среза: рамка вокруг закреплённого
окна во время подсветки при наведении использует `HighlightKind::Hover`;
`HighlightKind::Pin` (постоянная рамка) сборка содержит, но нигде не
вызывается — SPEC §5.2 явно требует «визуальной рамки нет» для уже
закреплённого окна, это правильно, просто оставляет один неиспользуемый
вариант enum.

## M9 — митоз окон (1 неделя)

Режим резки окна пополам: оригинал остаётся слева (сверху), справа (снизу)
открывается второй экземпляр того же приложения. Milestone закрыт целиком:
чистая геометрия (`rst-core::mitosis`), Win32-прослойка
(`rst-win32::window_mitosis`), визуал (`resticker::mitosis_overlay`) и сшивка
координатора (`enter_/exit_mitosis_mode`, `update_mitosis_hover`,
`start_mitosis`, `finish_mitosis`). Дизайн — `docs/M9_WINDOW_MITOSIS_DESIGN.md`,
полевые замеры — `docs/M9_MITOSIS_FIELD_NOTES.md`: окно «Блокнота» появляется
через 329 мс, Проводника — через 701 мс, single-instance-стабы умирают, а новое
окно появляется в отдельном процессе с тем же exe — поэтому отбор нового окна
идёт по exe-пути, а не по pid запущенного дочернего процесса.

- [x] Чистая геометрия в `rst-core::mitosis`: `split_fraction` с зажимом
      ±25 % от центра, `split_rects` без потери пикселя (сумма размеров
      половин всегда равна окну), `preflight` со всеми шестью отказами,
      `MIN_HALF_PX = 240`
- [x] Win32-прослойка `rst-win32::window_mitosis`: `process_private_bytes`,
      `available_physical_bytes`, `spawn_sibling` (DETACHED_PROCESS),
      `wait_for_sibling_window` с poll 150 мс / timeout 4 с; чистый отбор
      нового окна `match_sibling_window` по `hwnd ∉ known` и
      (`pid == sibling_pid` ИЛИ exe-путь без учёта регистра)
- [x] Визуал `resticker::mitosis_overlay`: `split_preview` (рамки половин,
      линия разреза 2 DIP, приглушённые запретные 25 %-полосы; красный
      предпросмотр `TooSmall`) и `cursor_hint` (плашка у курсора с удержанием
      в границах монитора)
- [x] Сшивка координатора: `enter_/exit_mitosis_mode` (крестовый курсор,
      снятие кликопрозрачности), `update_mitosis_hover` (окно под курсором +
      доля, денай-лист), `start_mitosis` (предполётные проверки, ужатие
      оригинала через `set_dwm_bounds`, фоновое ожидание второго окна),
      `finish_mitosis` (поставить клон или вернуть оригинал + баннер отказа),
      ветка `OverlayEvent::ToggleMitosisMode`
- [x] Хоткей `hotkeys.window_mitosis` (дефолт `Ctrl+Alt+F`, `MITOSIS_HOTKEY_ID`),
      настройка `settings.mitosis_max_memory_mb` (дефолт 4096)
- [x] Тексты всех шести отказов в `i18n::mitosis_refusal` (баннер оверлея;
      после отказов по факту запуска оригинал возвращается на место)

## Отложено (после 1.0)

Изначально в задумке был встроенный редактор в духе Photoshop. Он вынесен из 1.0 сознательно: по трудозатратам это отдельный продукт, сравнимый со всем остальным вместе взятым, и его отсутствие никак не мешает основному сценарию.

**Инструменты рисования (условно 2.0)**
- Слои рисования, превращающиеся в стикеры
- Кисть, ластик как маска (обратимая), фигуры, линии, текст
- Векторное представление, чтобы масштабирование стикера не портило качество
- Эффекты: размытие, свечение, тень, цветокоррекция
- Поддержка нажима графического планшета
- Сохранение слоя как редактируемого проекта, а не плоского PNG

**Прочий бэклог**
- Прозрачность и поворот для стикеров-окон
- Цветная рамка вокруг закреплённого окна (как в PowerToys)
- Условная видимость: показывать набор стикеров только при запуске определённой программы
- Автопереключение пресетов по контексту
- Стикеры-ярлыки: клик открывает файл или ссылку
- Анимированные переходы при показе и скрытии
- Веб-контент как стикер (кусок страницы, виджет)
- Захват области экрана в стикер (живое зеркало окна)
- Плагины
