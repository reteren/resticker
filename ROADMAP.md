# resticker — дорожная карта

Порядок вех выбран так, чтобы **каждая заканчивалась чем-то запускаемым**, и чтобы самые рискованные технические вещи проверялись как можно раньше, пока не поздно менять архитектуру.

Оценки — для одного разработчика, работающего с помощью Claude, при загрузке порядка 10–15 часов в неделю. Это ориентир, а не обещание. Реальность обычно оказывается в полтора раза дольше.

---

## Спайк S0 — проверка гипотезы (2–4 дня, **до всего остального**)

Самое главное в проекте — маска перекрытия и прозрачное композиционное окно. Если это не работает, вся архитектура другая. Поэтому это делается **первым**, одним грязным прототипом на 300 строк, который потом выбрасывается.

- [x] Win32-окно с `WS_EX_NOREDIRECTIONBITMAP | WS_EX_TOPMOST | WS_EX_TRANSPARENT`
- [x] D3D11 + DirectComposition, swapchain через `CreateSwapChainForComposition` с premultiplied alpha
- [x] Отрисовать один PNG с прозрачностью
- [x] Убедиться, что клики проходят насквозь
- [x] `SetWinEventHook` на `FOREGROUND` + `LOCATIONCHANGE`, вывод прямоугольников окон в консоль
- [x] Вырезать из PNG прямоугольник окна «Блокнот» через маску — и увидеть, что PNG действительно «уходит под» Блокнот
- [x] Замерить CPU при перетаскивании окна по экрану

**Критерий успеха:** картинка честно скрывается под Блокнотом, при перетаскивании окна CPU не превышает 2%.
**Если провалится:** пересматриваем раздел 3 ARCHITECTURE.md. Запасной вариант — `WS_EX_LAYERED` + `UpdateLayeredWindow` (медленнее) или отказ от выборочных слоёв в пользу двух режимов «поверх всего» / «на рабочем столе».

## M5 — анимация и видео (3–5 недель)

Самый непредсказуемый по срокам этап: FFmpeg всегда преподносит сюрпризы.

**M5a — GIF и анимированный WebP (~1 неделя)**
- [x] Декодирование всех кадров в текстурный атлас, анимация через смену UV
- [x] Собственные часы на стикер, планировщик ближайшего дедлайна
- [ ] Потоковый режим для очень длинных анимаций
- [x] APNG

**M5b — видео, программный декод (~1,5 недели)**
- [x] Сборка и линковка FFmpeg (LGPL shared, `--disable-gpl --disable-nonfree`)
- [x] Демуксер, декодер, очередь на 3 кадра, пул потоков
- [x] Луп через `av_seek_frame`
- [x] Конверсия YUV → RGB на GPU в шейдере (не через `sws_scale` на CPU)
- [x] Пауза декодирования для невидимых стикеров (`sticker_should_tick` +
      единая синхронизация cfg → живой `VideoSource` в `run()`, найдено и
      исправлено независимым ревью сшивки, `0f2b1ec`)

**M5c — аппаратный декод (~1 неделя)**
- [x] `d3d11va` hwaccel на общем `ID3D11Device` рендера, кадр как NV12
      `ID3D11Texture2D`, zero-copy путь по спеке (проверен GPU-тестом:
      побайтовое совпадение с программным декодом, mean_err=0.00). На
      стенде разработки (GTX 1070 Ti) драйвер NVIDIA отвергает создание SRV
      формата NV12/`TEXTURE2DARRAY` — сам рендер-путь этим ограничен и не
      верифицирован именно на этом железе, только на плоскостных R8/R8G8
      видах (задокументировано в коде/тестах rst-video::hwaccel)
- [x] Определение поддержки, безусловный fallback на программный декод при
      любой ошибке инициализации/неподдерживаемом формате (проверено)

**M5d — звук (~1 неделя)**
- [x] Микшер на `cpal`/WASAPI, ресемплинг (в `rst-video`, под реальный формат
      устройства — `rst-audio`/`AudioMixer`)
- [ ] Аудиочасы как ведущие, синхронизация видео (сознательно отложено —
      декодер пока пасётся по видео-PTS, docs/M5B_VIDEO_DESIGN.md §8)
- [x] Громкость на стикер (тулбар + `AudioSource::set_volume`)
- [x] Глобальный mute + хоткей (`hotkeys.mute_all`, `OverlayEvent::ToggleMuteAll`
      → `AudioMixer::set_muted`, дефолт `Ctrl+Alt+M`)
- [x] Приглушение невидимых стикеров (пауза декодера при невидимости
      останавливает и звук — тот же фикс `0f2b1ec`, что и выше)

**M5e — прозрачное видео (~0,5 недели)**
- [x] `yuva420p` (WebM/VP9), `yuva444p10le` (ProRes 4444, понижение 10→8 бит
      на CPU при распаковке — упрощение), `qtrle` (packed RGB → YUVA420P на
      CPU, swscale в сборке отключён)
- [x] Принудительный программный декод для таких файлов (`hwaccel_compatible()`
      — единый предикат, форматы с альфой не идут в M5c-путь) + альфа-осведомлённый
      `mainVideoPS` (premultiplied), UI-отметка — как факт для координатора,
      отдельной строки в интерфейсе не заведено

**Результат:** OBS-сцена в реальном времени на рабочем столе.

## M6 — стикеры-окна (1–2 недели)

Все низкоуровневые примитивы (`rst-win32`: `window_pick.rs`, `window_pin.rs`,
`virtual_desktops.rs`; `rst-core`: `window_follow.rs`; `rst-render`:
`window_highlight.rs`) готовы и покрыты тестами, но ничего не подключено к
координатору/UI — сама фича пользователю пока недоступна. Остаётся одна
большая интеграционная задача, не россыпь новых примитивов.

- [ ] Режим выбора окна с подсветкой под курсором (hit-test под курсором —
      `window_pick::window_at` — готов; рамка подсветки —
      `window_highlight::WindowHighlight` — готова; вход в режим по
      хоткею/панели и подключение обеих частей друг к другу в
      overlay_manager.rs — нет)
- [ ] `pin` / `unpin` через `SetWindowPos` + оконное свойство-маркер
      (`window_pin::WindowPins` — готов: `SetWindowPos` без активации,
      `SetPropW`-маркер, `AlreadyPinned`/`PinWindowGone`/`PinAccessDenied`;
      не подключён к `OverlayCommand`/тулбару)
- [ ] Гарантированное открепление при выходе, включая аварийный и `WM_ENDSESSION`
      (`WindowPins::unpin_all` есть, вызов из `run()` на выходе — нет)
- [ ] Перемещение и ресайз в пределах правил окна (чистая геометрия —
      `rst_core::window_follow::follow_window` — готова и протестирована;
      вызов на каждое изменение прямоугольника закреплённого окна из
      `WindowEvent::Changed` — нет)
- [x] `EVENT_OBJECT_DESTROY` → корректное удаление (`WindowPins::handle_snapshot`
      поверх существующего кэша `WindowTracker`, без второго WinEvent-хука —
      логика готова, эмитит `PinEvent::TargetDestroyed`; координатор ещё не
      скармливает снимки и не решает судьбу стикера по событию)
- [x] Обработка UIPI: понятное сообщение про права администратора
      (`Win32Error::PinAccessDenied` на `ERROR_ACCESS_DENIED` из
      `SetWindowPos`/`SetPropW`/`RemovePropW`, без обхода)
- [x] Виртуальные рабочие столы через `IVirtualDesktopManager` с fallback
      (`virtual_desktops::is_window_on_current_desktop` — публичный COM,
      Windows 10 1607+; `MoveWindowToDesktop` сознательно не реализован —
      публичный API не даёт перечислить GUID'ы столов, только
      недокументированные приватные интерфейсы, это и есть fallback, а не
      обход, ROADMAP это и просил; не подключено к координатору)

## Отложено (после 1.0)

Изначально в задумке был встроенный редактор в духе Photoshop. Он вынесен из 1.0 сознательно: по трудозатратам это отдельный продукт, сравнимый со всем остальным вместе взятым, и его отсутствие никак не мешает основному сценарию.

**Инструменты рисования (условно 2.0)**
- Слои рисования, превращающиеся в стикеры
- Кисть, ластик как маска (обратимая), фигуры, линии, текст
- Векторное представление, чтобы масштабирование стикера не портило качество
- Эффекты: размытие, свечение, тень, цветокоррекция
- Поддержка нажима графического планшета
- Сохранение слоя как редактируемого проекта, а не плоского PNG

**Прочий бэклог**
- Прозрачность и поворот для стикеров-окон
- Цветная рамка вокруг закреплённого окна (как в PowerToys)
- Условная видимость: показывать набор стикеров только при запуске определённой программы
- Автопереключение пресетов по контексту
- Стикеры-ярлыки: клик открывает файл или ссылку
- Анимированные переходы при показе и скрытии
- Веб-контент как стикер (кусок страницы, виджет)
- Захват области экрана в стикер (живое зеркало окна)
- Плагины
