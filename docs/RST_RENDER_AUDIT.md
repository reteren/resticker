# rst-render — технический аудит

Статус: **аудит, без изменений кода**. Прочитаны целиком все модули
`crates/rst-render/src/` (4341 строка): `device.rs`, `window_target.rs`,
`texture.rs`, `shader.rs`, `sprite.rs`, `selection.rs`, `marquee.rs`, `text.rs`,
`icons.rs`, `ui_textures.rs`, `widgets.rs`, `error.rs`, `lib.rs`; пример
`examples/overlay_demo.rs` и GPU-smoke `tests/gpu_smoke.rs`. Проверены
потребители API (overlay_manager.rs, toolbar.rs, cursor_panel.rs,
confirm_dialog.rs), свежие коммиты крейта (`ad8bc18` Device/WindowTarget split —
M3 step 2, `32a3b0e` UiTextures, `22c8da3`/`8cba808`), сверка с
`docs/M3_PREP_NOTES.md` §4 и `docs/M3_DEVICE_RECOVERY_REVIEW.md`. Прогон:
87 юнит-тестов (без GPU) зелёные, GPU-smoke в игноре, clippy `-D warnings` и
fmt чистые.

**Общий вердикт:** крейт здоровый — архитектура «один `Device` на процесс +
`WindowTarget` на монитор» (M3 step 2) чистая и задокументированная,
premultiplied alpha проведён end-to-end консистентно, вся чистая геометрия
покрыта тестами без GPU, unsafe-блоки везде с SAFETY-комментариями, публичная
поверхность в основном востребована. Живых багов не найдено. Одна заметная
проблема структуры — **неиспользуемый дубликат кэша текстур UI**
(`UiTextures`/`TextureFactory` в крейте против собственного `UiTextureCache` в
координаторе); остальное — perf-заметки и мелкие замечания.

---

## 1. Что корректно (не тратить время на повторную проверку)

- **Разделение `Device`/`WindowTarget`** (ad8bc18): текстуры устройства живут
  независимо от целей; ресайз окна и `DEVICE_REMOVED` пересоздают только цель
  (swapchain/RTV), текстуры не трогаются. `resize` корректно отпускает RTV
  **до** `ResizeBuffers` (иначе DXGI_ERROR_INVALID_CALL); нулевой размер — не
  ошибка, кадры пропускаются (`rtv()` → `None`). Восстановление после потери
  устройства пересоздаёт и устройство, и цели, и текстуры (полный путь) —
  согласуется с M3_DEVICE_RECOVERY_REVIEW.
- **Premultiplied alpha end-to-end**: straight→premultiply на CPU при загрузке
  (texture.rs:143), PS умножает premultiplied цвет на opacity (shader.rs:51 —
  корректно именно для premultiplied), blend `ONE`/`INV_SRC_ALPHA`. Нигде нет
  «двойного» умножения или straight-текстуры в premultiplied-цепочке.
- **`SpriteParams`**: `repr(C)` 48 байт, оффсеты 0/16/32 — закреплены юнит-тестом
  против HLSL-упаковки (урок спайка S0). Трансформация DIP→физика в
  `placement_to_physical` покрыта тестом; координаты NDC в VS (Y-флип) верны.
- **DeviceLost**: маппинг в `present()` (`DXGI_ERROR_DEVICE_REMOVED`/`RESET` →
  `RenderError::DeviceLost`), пересоздание инициируется координатором —
  единственный путь. `broken`-флаг (3f2dc47) на уровне координатора не требует
  правок в крейте.
- **Чистая геометрия без GPU**: selection/marquee/text/icons/ui_textures не
  знают про D3D11; хит-тест виджетов переиспользует `rst_core::hittest::to_local`
  (дублирования аффинной математики нет); NaN/вырожденные входы везде
  отфильтрованы (marquee_visuals, dash_segments, box_contains,
  validate_texture_data, rasterize empty-string → 1×8).
- **Immediate-mode виджеты**: retained-состояния; захват указателя и
  клавиатурный фокус в `Panel` (роутинг Move/Up при захвате, `on_blur`-откат
  поля при потере фокуса); одноразовые флаги (`take_click`/`take_changed`/
  `take_submitted`/`take_cancelled`); ошибки фабрики в `UiTextures` **не**
  кэшируются (проверено тестами).
- **Владение и безопасность**: COM-объекты — умные указатели windows-rs,
  `Texture::Clone` = `AddRef`; держатель текстуры живёт рядом с SRV; каждый
  unsafe-блок снабжён SAFETY-комментарием; `Device` намеренно `!Send`
  (документировано). Шейдер компилируется в рантайме через системный
  `d3dcompiler_47.dll` — без лишних зависимостей.
- **Тестовое покрытие**: 87 юнит-тестов без GPU (мок-фабрика в ui_textures,
  чистая математика в остальных); GPU-слой (Device/WindowTarget/Texture)
  покрыт ignored-смоук-тестом и примером `overlay_demo` — приемлемо для
  платформенного кода.

## 2. Найденные проблемы

### 2.1 (средне) `UiTextures`/`TextureFactory` — неиспользуемый дубликат кэша текстур UI

- **Где:** rst-render экспортирует `UiTextures<T>` + `TextureFactory`
  (lib.rs:46, ui_textures.rs), но **ни один потребитель их не использует**:
  grep по крейтам — только реэкспорт и собственные тесты на мок-фабрике.
  Координатор держит собственную копию кэша (`UiTextureCache` в
  overlay_manager.rs:636-685: `fill_texture`/`text_texture`/`icon_texture` с
  теми же ключами: цвет; строка+цвет; `Icon`).
- **Что:** две реализации одного и того же. rst-render-версия (32a3b0e)
  написана под тестируемость (параметризация фабрикой), но в проде не
  участвует и может разойтись с живой; локальная — без мок-тестов, но рабочая.
  Мёртвый публичный API в крейте, который позиционируется как «рендерер» —
  дублирование логики и риск.
- **Рекомендация:** перевести координатор на `rst_render::UiTextures`
  (API готов, тесты есть, `Device` уже реализует `TextureFactory`) и удалить
  локальный `UiTextureCache`; либо снять экспорт неиспользуемого кэша из
  lib.rs. Решение за координатором.

### 2.2 (низкое) `Device::draw` — Map/Unmap константного буфера на каждый спрайт

- **Где:** device.rs:262-297: `Map(WRITE_DISCARD)` → `Unmap` → `Draw` в цикле
  по спрайтам — один CPU-маппинг на спрайт. Map — синхронизирующая операция;
  при ~25 стикерах и редких кадрах (ADR-006) некритично, но паттерн «маппить
  буфер на каждый вызов» — известный антипаттерн D3D11.
- **Рекомендация (опционально):** писать все `SpriteParams` одним Map'ом
  (буфер размера `N×48` или один cbuffer на спрайт с динамическим оффсетом).
  Perf-заметка, не блокер.

### 2.3 (низкое) NaN не фильтруется в `Device::draw`

- **Где:** device.rs:266: `if sprite.placement.w <= 0.0 || sprite.placement.h <=
  0.0 { continue; }` — для NaN оба сравнения ложны → NaN-размер уходит в
  шейдер (на практике клип/невидимость, не падение).
- Остальные модули крейта NaN фильтруют везде (marquee/text/selection/
  box_contains); здесь гард неполон. На практике NaN-placement не создаётся
  (валидация в hittest::drawable), но `!w.is_finite() || !h.is_finite()` сделал
  бы гард симметричным остальному коду.

### 2.4 (низкое) Numpad-цифры не вводятся в числовое поле прозрачности

- **Где:** перевод VK → `Key` в координаторе (overlay_manager.rs:1982)
  покрывает только `0x30..=0x39` (основной ряд); `VK_NUMPAD0..9` (`0x60..0x69`)
  в `Key::Digit` не транслируются. Поле прозрачности тулбара не реагирует на
  цифры с нампада — UX-деталь, не баг модели.

### 2.5 (замечание) `Key::Digit` — контракт «доверяй вызывающему»

- `NumericField::insert_digit` делает `char::from(b'0' + digit)`: при `digit >
  9` это паника в debug (u8-арифметика/char::from) на потоке координатора.
  Единственный call-site (перевод VK) выдаёт только 0–9, но виджет сам не
  защищён. Clamp/валидация в виджете сделала бы API паникобезопасным.

### 2.6 (замечание) «☐» в подписи «☐ Don't ask again» рисуется fallback-глифом

- Символа U+2610 в таблице битового шрифта нет (text.rs:30-235) →
  `glyph_for` возвращает контурный квадрат, который визуально похож на
  неотмеченный чекбокс. Совпадение, а не гарантия: при расширении набора
  глифов или изменении fallback вид переключателя сломается. Стоит либо
  добавить глиф ☐, либо заменить подпись.

### 2.7 (замечание) `CHECKERBOARD_HLSL` — неиспользуемый мёртвый код

- selection.rs:230-264: HLSL-вариант шахматки документирован как «точка
  расширения для M2», но не задействован — шахматка рисуется CPU-текстурой
  (`checkerboard_tile`, используется overlay_manager.rs:3557). Проверяется
  только строковыми contains-тестами. Держать как задел или удалить — решение;
  минимум — пометить срок жизни.

## 3. Замечания и наблюдения

- **`Sprite` — снимок `Placement`/`Transform`**: спрайт несёт копию геометрии
  модели; синхронизация cfg↔спрайт — инвариант bin-крейта (все пути пишут оба
  одним значением; проверено в M3_STEP7_REVIEW §1.5). Осознанный выбор,
  зафиксировать как контракт в доке крейта.
- **Синхронный декод изображений** (`load_image`) на потоке координатора;
  даунскейл >4096 и кэш — зона rst-media (документировано в device.rs:193).
  При больших файлах возможна задержка цикла — задел.
- **`Present(1, 0)` — vsync**: при двух redraw подряд в одном кадре второй
  Present может проскочить; на практике безвредно (перерисовка по событию).
- **Публичная поверхность**: `Glyph`/`glyph_for`/`width_up_to`/
  `SelectionVisuals`/`MarqueeVisuals` — тип-результаты/внутренности, экспорт
  шире потребления; безвредно, но поверхность можно сузить.
- **`Icon::Layers`/`PresetSave`/`PresetLoad`** — определены, сгенерированы
  (`icon_rgba` покрыт тестами для всех 14), в UI не используются (задел M4/M5).
- **`Slider`/`NumericField` конструкторы паникуют при `min >= max`** — контракт
  валидации, вызывающий слой строит диапазоны константами; приемлемо.
- **`Panel::pointer_event(Up)` вне захвата**: `consumed: self.hit_test(pos)` —
  Up по кнопке без предшествующего Down поглощается, но клика не создаёт
  (нужен `armed`) — корректно.
- **GPU-smoke и пример**: `gpu_smoke.rs` (ignored) и `overlay_demo.rs` —
  единственное живое покрытие D3D-слоя; при M3-перестановках (WindowTarget per
  monitor) держать в актуальном состоянии (сейчас — да).

## 4. Приоритеты для координатора

1. **Дубликат кэша текстур UI (п. 2.1)** — перевести координатор на
   `rst_render::UiTextures` и удалить локальный `UiTextureCache`, либо снять
   экспорт; убрать вторую реализацию одной логики.
2. **Perf-мелочи (п. 2.2)** — один Map на кадр в `Device::draw` (опционально).
3. **NaN-гард в draw (п. 2.3)** и numpad-цифры (п. 2.4) — мелкие фиксы по
   одному месту.
4. **Замечания (п. 2.5–2.7)** — глиф ☐ / паникобезопасность Digit / судьба
   `CHECKERBOARD_HLSL`.
