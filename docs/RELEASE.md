# Что нужно, чтобы выпустить resticker

Составлено 2026-09-07 по замерам на живой машине, а не по ощущениям. Каждый пункт
сформулирован так, чтобы его можно было **проверить**, а не «посчитать сделанным».

Документ отвечает на один вопрос: что отделяет текущее дерево от версии, которую не стыдно
дать чужому человеку. Веха M8 в `ROADMAP.md` описывает то же самое списком задач; здесь —
состояние и порядок.

---

## 1. Готово и проверено

| Что | Чем подтверждено |
|---|---|
| Тихий старт, трей, автозапуск, единственный экземпляр | M0–M8 в `ROADMAP.md`, тесты крейтов |
| Инсталлятор NSIS собирается | `pnpm tauri build --bundles nsis` → `resticker_0.1.0_x64-setup.exe` |
| Атомарная запись конфига, повреждённый файл отводится в сторону | `rst-core/src/config.rs`, тесты `config_io.rs` |
| Паника логируется с бэктрейсом | хук в `main.rs`, поставлен после живого случая 2026-08-18 |
| Конфликт хоткея виден человеку | тост трея + собственный баннер оверлея |
| **CPU в покое 0,024 %** при потолке 0,3 % | замер 2026-09-07: 20 с на живом процессе, 16 ядер |

## 2. Блокеры

### 2.1 Логи

**Было:** каталог логов рос без предела — 75 МБ за 24 дня, худший день 42 МБ; 96 % строк
за день (6261 из 6505) давала временная диагностика, писавшая строку в файл **на каждое
движение мыши во время перетаскивания**, синхронно под мьютексом.

**Сделано 2026-09-07:** диагностика снята из обоих мест (`rst-win32/src/input.rs`,
`resticker/src/overlay_manager.rs`); дедуп повторных `WM_MOUSEMOVE`, ради которого её
ставили, остался. Удержание логов по возрасту и объёму — в `resticker/src/logging.rs`.

**Проверка:** после часа обычной работы в каталоге логов не должно появляться мегабайтов;
перетаскивание стикера не должно добавлять ни строки.

### 2.2 CI не собирает проект

С появления крейта `rst-video` (веха M5b) в `.github/workflows/ci.yml` нет `FFMPEG_DIR`, а
`crates/rst-video/build.rs` без неё паникует — падают и `cargo test --workspace`, и
`cargo build --workspace`. Плюс триггер стоял только на `main`/`master`, а работа идёт в
ветке.

**Проверка:** зелёный прогон на pull request из рабочей ветки, в артефактах — собранный
инсталлятор.

### 2.3 Подписи нет

`bundle.windows` пуст, `publisher` не задан. Каждая установка встретит человека
SmartScreen'ом «Windows защитила ваш компьютер», и это худшее первое впечатление из
возможных.

**Решение за владельцем проекта.** Варианты, честно:

* **OV-сертификат** (обычный code signing) — дешевле, но репутацию SmartScreen набирает
  сам, неделями, и до этого предупреждение остаётся;
* **EV-сертификат** — предупреждения нет с первого дня, дороже и требует аппаратного
  токена/HSM;
* **без подписи** — тогда в README и на странице релиза нужен честный абзац «Windows
  покажет предупреждение, вот почему и вот как продолжить». Молча оставлять человека с
  этим экраном нельзя.

Технически: подпись подключается в `tauri.conf.json` (`bundle.windows.certificateThumbprint`
и соседние поля) плюс секрет в CI. Пока сертификата нет — не включать.

### 2.4 Обновлений нет

Плагина `updater` в `tauri.conf.json` нет. Для резидентной утилиты это значит: человек
навсегда останется на той версии, которую скачал, и следующее исправление до него не
доедет никогда.

Минимальный рабочий вариант: `tauri-plugin-updater` + статический `latest.json` на GitHub
Releases + пара ключей (`tauri signer generate`), приватный — в секретах CI. Требует
решения по 2.3: апдейтер проверяет **свою** подпись пакета, а SmartScreen — подпись
издателя; это разные вещи, и одна другую не заменяет.

## 3. Не блокеры, но до релиза

### 3.1 Показатели SPEC §13 не подтверждены

`SPEC.md` раздел 13 задаёт таблицу (CPU/RAM/GPU по сценариям) для **25 стикеров**.
Замер 2026-09-07 на живом процессе с **пятью** стикерами (один — видео): private working
set **182 МБ** при потолке 200 МБ, 93 потока, 938 хендлов. То есть по памяти цель, скорее
всего, не выполняется, и это надо измерить, а не обсуждать.

Инструмент — `scripts/measure.ps1` (только чтение, ничего не запускает и не останавливает).
Нужны два прогона: 25 стикеров в покое и суточный на утечки (пункт M8 «прогон 24 часа»).

### 3.2 Деинсталляция

Установка — `currentUser`, автозапуск программа пишет сама в
`HKCU\...\CurrentVersion\Run`. При удалении ключ автозапуска и папки данных
(`%APPDATA%\resticker`, `%LOCALAPPDATA%\resticker`) оставались. Ключ, указывающий на
удалённый exe, тормозит вход в систему.

**Проверка:** после удаления — нет значения в `Run`; данные удаляются только если человек
согласился, а в тихом режиме (`/S`) сохраняются.

### 3.3 Падение должно быть заметно

Профиль релиза — `panic = "abort"`, подсистема `windows`. Паника в любом из ~90 потоков
мгновенно убивает процесс; в лог всё пишется, но для человека программа просто исчезает.
Нужно, чтобы при следующем запуске он узнал, что случилось и где лог.

### 3.4 README и страница релиза

README переписан, но раздел «Скриншоты» — явный `TODO`, гифок нет, страница GitHub Releases
не заведена. Скриншоты снимаются только на живой машине с настоящими стикерами: это
пять минут работы владельца, а не задача сборки.

## 4. Известные ограничения, которые надо назвать вслух

Не дефекты, а осознанные решения — но человек должен узнать о них из README, а не опытным
путём:

* **жест группы работает в пределах одного монитора** (координаты у мониторов свои,
  ADR-010; SPEC.md 3.6);
* **поворота у группы нет** — повернуть её значило бы вращать каждый стикер вокруг чужого
  центра;
* **позиция перемотки — только для одиночного выделения**, она у каждого видео своя;
* **язык один, английский**; поле `language` в конфиге читается ради совместимости, но ни
  на что не влияет;
* **скрытые стикеры полностью интерактивны в режиме редактирования** (SPEC.md 3.7) — их
  видно шахматкой, и они участвуют в магните и в выделении.

## 5. Порядок

1. Логи (2.1) и CI (2.2) — дешёво, измеримо, разблокирует всё остальное.
2. Деинсталляция (3.2) и видимость падений (3.3) — обе про доверие к программе.
3. Замеры (3.1): 25 стикеров + суточный прогон. Здесь может вскрыться работа по памяти —
   лучше узнать до релиза, чем после.
4. Решение по сертификату (2.3), затем апдейтер (2.4).
5. Скриншоты, README, страница релиза (3.4).
