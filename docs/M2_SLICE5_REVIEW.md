# M2 — ревью среза 5: фиксы 5 багов ревью среза 4/4b

Статус: **ревью, без изменений кода**. Коммиты `e28b400` («Sticker::new_pasted»,
`crates/rst-core/src/model.rs` + `tests/model_serde.rs`) и `be1d380` («address 5
bugs from independent review», `crates/resticker/src/overlay_manager.rs`);
`fb41da6` (multi-select ops) входит в диапазон `git log -3`, но ни
`overlay_manager.rs`, ни `model.rs` не трогает — вне рамок этого ревью. Прочитаны
диффы обоих коммитов и актуальный код `overlay_manager.rs` в местах фиксов
(`begin_delete`, модал `MouseUp`, `CaptureLost`, `apply_gesture`,
`paste_from_clipboard`, `add_sticker`, `toggle_edit_mode`, `perform_undo/redo`);
call-site'ы `ops::delete` и `cleanup_pasted_file` проверены grep'ом по всем
крейтам; `rubber_band`/`intersecting_ids` сверены на вырожденные прямоугольники.
Интерактивного прогона не было (static review: build/clippy/test зафиксированы
в самих коммитах).

**Общий вердикт:** все пять фиксов корректны по существу — порядок чистки и
снимок настроек выдержаны, `before` у марки закрывает `CaptureLost`, порог гейтит
только переход, клик мимо модала больше не отменяет диалог. Проблемы — два новых
следствия файловой чистки (`cleanup_pasted_file`), которых не было до фикса:
дублированный Pasted-стикер делит с оригиналом один файл (удаление одного ломает
другого) и undo удаления воскрешает Pasted-стикер с уже удалённым файлом; плюс
три известных/предсуществующих дисковых «сироты».

## 1. Проверено по явным вопросам задачи

### 1.1 `cleanup_pasted_file` всегда до `ops::delete`, путей «после» нет

`ops::delete` в bin-крейте вызывается ровно в двух местах, и в обоих чистка идёт
**до** удаления:

- `begin_delete`, быстрый путь без модала (overlay_manager.rs:732-735):
  `commit_undo_snapshot` → `cleanup_pasted_file(cfg, id)` → `ops::delete(cfg, id)`.
- Модал, кнопка «Удалить» (overlay_manager.rs:1165-1170): синхронизация снимка →
  `commit_undo_snapshot` → `cleanup_pasted_file(cfg, *id)` → `ops::delete(cfg, *id)`.

`cleanup_pasted_file` ищет стикер по id в `cfg` перед `remove_file` — после
`ops::delete` он бы не нашёлся, и файл утёк бы. Порядок корректный, `File`/`Window`
чистка не трогает. Других путей удаления стикеров нет (grep: `ops::delete` и
`StickerSource::Pasted` больше нигде не пересекаются).

### 1.2 `CF_HDROP Files` — утечки истории нет, снимок один на пачку

Ветка `Files` (overlay_manager.rs:857-881): `before = cfg.clone()` до цикла, внутри
цикла `add_sticker` возвращает `bool`, в конце — **один** `commit_undo_snapshot(edit,
before)` только если хоть один файл добавился. Проверено:

- несколько `add_sticker` подряд → один шаг undo на всю пачку, `Ctrl+Z` снимает
  целиком (нет накопления пустых/частичных шагов);
- частичный успех (часть файлов не декодировалась) → шаг всё равно один, покрывает
  добавленное;
- полный провал (все не декодировались) → `added == false`, снимок не коммитится,
  пустого шага истории нет (закрывает пункт 7 ревью среза 4);
- `sprites`/`cfg.stickers` пополняются только реально загруженными файлами — «утечки
  объектов» нет.

Дисковых утечек именно эта ветка не создаёт: `CF_HDROP` — файлы пользователя, а не
материализованные копии.

### 1.3 `Gesture::Marquee::before` во вложенных сценариях — корректно

`before` снимается в `MouseDown` на фоне (overlay_manager.rs:1053-1056), до первого
порогового `Move` — ровно «выделение на момент начала марки». Все пути завершения
марки:

- **`CaptureLost`** (overlay_manager.rs:1243-1256): `selection.clear()` + `select` по
  `before` — восстанавливается точный прежний набор (и его порядок — `ids()` в том
  же порядке). Симметрично остальным жестам «потеря захвата = откат».
- **`MouseUp`** (overlay_manager.rs:1208-1218): `before` не используется —
  выделение остаётся результатом `rubber_band`, это «коммит» марки. Корректно.
- **Esc → `toggle_edit_mode`** (вложенный сценарий из задачи): жест берётся
  (overlay_manager.rs:566), для марки `Gesture::start()` — `None`, `apply_transform`
  не зовётся (откатывать в модели нечего); марка-визуал сбрасывается, а при выходе
  (`!active`) `edit.selection.clear()` (overlay_manager.rs:586). `before` просто
  дропается неиспользованным — **частичного выделения не остаётся**, поведение
  согласовано с «выход из режима = снять выделение». Не асимметрия, а корректный
  откат.
- **Мёртвые id в `before` невозможны**: пока жест активен, `handle_key` блокирует
  историю/удаление/дублирование (overlay_manager.rs:768), а Esc единственный, кто
  выходит — через `toggle_edit_mode`, который жест и снимает. `select(id)` не может
  сослаться на удалённый стикер.

## 2. Фиксы по пунктам ревью среза 4 — корректны

- **Пункт 1 (Pasted + удаление файла).** `Sticker::new_pasted` создаёт
  `StickerSource::Pasted { path }` (model.rs), serde даёт `"kind": "pasted"`
  (тест `new_pasted_sticker_uses_pasted_source`). Загрузка текстур (старт +
  `resync_sprites`) переведена на общий `sticker_image_path`, принимающий и `File`, и
  `Pasted` — без этого фикса Pasted-стикеры молча не рендерились бы. Сам файл чистится
  в обоих путях удаления (§1.1). **Новые следствия — §3.1, §3.2.**
- **Пункт 2 (снимок настроек модала).** Синхронизация `snapshot.settings =
  cfg.settings.clone()` перед коммитом (overlay_manager.rs:1165-1166) корректна и
  полна: пока модал открыт, единственное, что может измениться в `cfg`, — тумблер
  «Don't ask again» (клавиши, кроме Esc, и мышь полностью заблокированы веткой
  модала; Esc отменяет без коммита). Других полей в «окне снимка» нет. `Ctrl+Z` после
  удаления больше не откатывает глобальный тумблер.
- **Пункт 3 (`CaptureLost` возвращает выделение марки).** Корректно, см. §1.3.
- **Пункт 4 (порог гейтит только переход).** `edit.marquee_started ||
  |w|>=порог || |h|>=порог` (overlay_manager.rs:1298-1301): до старта порог по-прежнему
  отличает клик от протяжки, после старта обновление безусловное. Сжатие рамки обратно
  ниже порога больше не «замораживает» выделение. Проверено, что `rubber_band` с
  вырожденным прямоугольником безопасен: `intersecting_ids` → `normalized()` возвращает
  `None` для нулевого размера/NaN → пустое выделение, без NaN/паники (selection_set.rs:176-193,
  197-206). То есть «стянул марку в точку» = выделение честно сходится к пустому;
  `MouseUp` при `started=true` оставляет его как есть. Это и есть целевое поведение.
- **Пункт 6 (клик мимо модала не закрывает).** Ветвление (overlay_manager.rs:1152-1205)
  корректно: `ID_DELETE` → коммит+удаление; `ID_DONT_ASK` → тумблер + модал остаётся;
  `ID_CANCEL` → закрыть (confirm не перекладывается); всё прочее (мимо модала, по тексту
  сообщения) → `edit.confirm = Some(confirm)`, диалог остаётся. Согласуется с
  M2_WIRING_PLAN §5 «модал модален». Esc по-прежнему закрывает через `handle_key`
  (overlay_manager.rs:775-781).
- **Пункт 7 (пустой шаг undo при вставке).** Оба пути (`Files`, `Png`/`Bmp`) коммитят
  снимок только при реально добавленном стикере, см. §1.2. Частичный успех — один шаг.

## 3. Найденные проблемы (новые следствия чистки файлов)

### 3.1 Дублированный Pasted-стикер делит файл с оригиналом — удаление одного ломает другого

`ops::duplicate` (ops.rs:116) клонирует стикер целиком, включая
`StickerSource::Pasted { path }` — копия ссылается на **тот же** материализованный
файл, что и оригинал. `Ctrl+D` по вставленному стикеру (overlay_manager.rs:812-827)
создаёт такую копию.

До фикса это было безвредно: Pasted-стикеры не чистились вообще, и общий путь
работал. После фикса `cleanup_pasted_file` удаляет файл при удалении **любого** из
пары:

- удалить копию → файл удалён, оригинал остаётся в конфиге, но перестаёт рендериться
  (путь мёртв, `resync_sprites`/стартовая загрузка логируют и пропускают);
- удалить оригинал → сломана копия.

Симметрично работает и для мульти-дубликата (Ctrl+D по нескольким Pasted). Никакой
код не знает о «двух стикерах на один путь», чистить файл корректно может только
**последний** живой ссылающийся стикер.

Это не было в ревью среза 4 и появилось именно в результате фикса п.1. Тестов на
дубликат Pasted нет (rst-core тесты дублируют File-стикер по умолчанию).

### 3.2 Undo удаления воскрешает Pasted-стикер с уже удалённым файлом

Снимок при удалении берётся **до** чистки (в обоих путях), т.е. на undo-стеке лежит
конфиг, где Pasted-стикер ещё есть, — но его файл к моменту undo уже удалён
(«delete/undo-of-delete removes the materialized file» — так и заявлено в коммите).
`Ctrl+Z` после удаления вставленного стикера:

1. восстанавливает конфиг со стикером `Pasted { path }`;
2. `resync_sprites` не находит файл → стикер молча не рендерится;
3. `perform_undo` сохраняет этот конфиг в config.json (overlay_manager.rs:677) —
   битый стикер закрепляется на диске и переживает перезапуск.

До фикса файл не удалялся никогда, и undo удаления возвращал полностью рабочий
стикер. Пользователь жмёт «отменить удаление» и получает невидимый стикер в конфиге.
Либо принимаем как осознанную семантику («undo удаления Pasted возвращает заглушку»)
и фиксируем, либо undo должен не воскрешать Pasted без файла (например, отбрасывать
такой стикер при undo) — решение за координатором.

### 3.3 Известные дисковые «сироты» (были и до фикса, но теперь заметнее)

- **Undo самой вставки** оставляет материализованный файл: `Ctrl+V` → стикер добавлен,
  файл `pasted/<uuid>.png` на диске → `Ctrl+Z` убирает стикер из конфига, но файл
  остаётся. Никто его не чистит — SPEC 2.5 чистка завязана на delete, а не на undo
  вставки.
- **Неудачный декод после материализации** (ветка `Png`/`Bmp`,
  overlay_manager.rs:886-894): `materialize` создаёт файл, `add_sticker` не смог его
  загрузить → возвращается `false` без коммита, но `<uuid>.png` остаётся сиротой.
  Редкий путь (буфер содержал изображение), но с учётом новой инфраструктуры чистки
  напрашивается удаление файла прямо в этом else.

### 3.4 Замечание о миграции (не баг, но стоит зафиксировать)

До `e28b400` все вставки писались как `StickerSource::File` (проверено ревью среза 4).
В существующих конфигах такие стикеры остаются `"kind": "file"`: рендерятся и
загружаются нормально, но новую чистку не получат никогда (это не `Pasted`), и их
файлы продолжат накапливаться. Потери данных нет; миграция конфигов не требуется,
но ожидание «SPEC 2.5 выполнен» верно только для вставок после фикса.

## 4. Что проверено и корректно (не тратить время на повторную проверку)

- **Порядок и полнота чистки**: все `ops::delete` (2 call-site'а) предварены
  `cleanup_pasted_file`; `File`/`Window` не чистятся; ошибочное удаление несуществующего
  файла — только warn, не паника (overlay_manager.rs:648-660).
- **Загрузка Pasted**: `sticker_image_path` единый для `File`/`Pasted`, покрыт и в
  стартовой загрузке (overlay_manager.rs:404-410), и в `resync_sprites`
  (overlay_manager.rs:614-621); сериализация `kind:"pasted"` покрыта тестом
  `model_serde.rs`.
- **Снимок настроек**: тумблер — единственное мутируемое поле в «окне» модала; синк
  на коммит полон.
- **Марка**: `before` корректно снимается/восстанавливается/дропается во всех четырёх
  сценариях (CaptureLost, MouseUp, Esc-выход, обычный жест); вырожденная рамка →
  пустое выделение без NaN.
- **Модал**: клик мимо/по сообщению не закрывает; `ID_CANCEL` и Esc закрывают; модал
  остаётся модальным (события наружу не уходят).
- **Вставка**: один снимок на пачку, пустого шага истории нет, `CF_HDROP` файлы
  пользователя не чистятся и не орфанятся.

## 5. Приоритеты для координатора

1. Дубликат Pasted делит файл с оригиналом (п. 3.1) — общий путь `Ctrl+D`/мульти-дубль
   по вставленным стикерам; чистка должна удалять файл только при удалении последнего
   ссылающегося стикера (или дубликат должен получать собственный файл).
2. Решить семантику undo удаления Pasted (п. 3.2): воскрешать битую заглушку или
   отбрасывать стикер без файла.
3. Докрутить чистку «сирот» вставки (п. 3.3): undo вставки и неудачный декод.
4. Зафиксировать миграционный статус старых `kind:"file"` вставок (п. 3.4) — если
   захочется вычищать и их, нужен отдельный путь.
