# Митоз окон — дизайн

Запрос пользователя 2026-09-01. Новая функция верхнего уровня: разрезать
чужое окно пополам так, что слева (сверху) остаётся оригинал, а справа
(снизу) открывается ВТОРОЙ ЭКЗЕМПЛЯР того же приложения. Сценарий-мотив —
два проводника рядом, но работает для любого приложения, которое умеет
открыть второе окно.

## 1. Пользовательский сценарий

1. `Ctrl+Alt+F` (новый хоткей `hotkeys.window_mitosis`) — включается **режим
   резки**. Курсор становится крестом, оверлей на всех мониторах перестаёт
   быть кликопрозрачным.
2. Курсор над чужим окном — окно подсвечивается, поперёк него идёт линия
   разреза, а обе будущие половины обведены рамкой: пользователь видит
   результат до клика.
3. Ось выбирается сама, по тому, к какому краю окна ведут курсор: к
   боковому — линия горизонтальная, к верхнему или нижнему — вертикальная
   (курсор показывает край, в который линия упирается). Переключения
   колесом и `Tab` больше нет — правка по живому фидбэку 2026-09-01.
4. Левый клик — разрез. Режим выключается сразу (одно нажатие — один разрез).
5. `Esc` или повторный `Ctrl+Alt+F` — выйти без разреза.

Отказ (окно слишком тяжёлое, приложение не открывает второе окно и т.п.)
показывается баннером оверлея (`show_banner`) и тоже выключает режим.

## 2. Геометрия

* Ось `Vertical` — разрез вертикальной линией, половины **слева/справа**.
  Оригинал — левый. Ось `Horizontal` — половины **сверху/снизу**, оригинал
  верхний.
* Положение разреза задаёт курсор, но **зажато в ±25 % от центра**:
  доля разреза `fraction ∈ [0.25, 0.75]`. Отрезать «совсем чуть-чуть»
  нельзя — это и требование пользователя, и защита от нечитаемого окна.
* Половина меньше `MIN_HALF_PX` физических пикселей по режущей оси — отказ
  `TooSmall`. Разрезать окно 300 px пополам бессмысленно.
* Исходный прямоугольник — `WindowInfo::rect` (границы DWM). Ставятся окна
  через `WindowPins::set_dwm_bounds`, который компенсирует невидимую рамку и
  сам приводит развёрнутое окно в нормальное состояние.

## 3. Отказы

| Отказ | Когда |
|---|---|
| `TooHeavy` | приватная память процесса > `settings.mitosis_max_memory_mb` (дефолт 4096) |
| `NotEnoughMemory` | приватная память процесса > свободной физической памяти системы |
| `TooSmall` | половина по режущей оси меньше `MIN_HALF_PX` |
| `NoExePath` | у окна не читается путь к exe (защищённый процесс) |
| `SpawnFailed` | процесс не завёлся |
| `SingleInstanceApp` | приложение числится в `settings.mitosis_single_instance_apps` — отказ ДО движения окна |
| `NoSecondWindow` | второй экземпляр не показал НОВОГО окна за отведённое время |

`NoSecondWindow` — честный отказ по факту: приложение лишь сфокусировало
существующее окно, а дочерний процесс тут же вышел. Заранее это не
определить ни по exe, ни по процессу.

Именно поэтому отказ **обучающий**: два подряд по одному exe заносят
приложение в `settings.mitosis_single_instance_apps`, и дальше оно
отклоняется мгновенно, как `SingleInstanceApp`. Дефолт списка —
`discord.exe` и `spotify.exe`, и только они: оба названы пользователем по
живому опыту 2026-09-01. Дописывать туда «очевидно одно-оконные»
приложения по памяти нельзя — ровно такое предположение про Проводник
опровергнуто замером (§3.2 полевых заметок).

**Откат.** Оригинал ужимается СРАЗУ (мгновенный отклик), исходный
прямоугольник запоминается. Любой отказ ПОСЛЕ ужатия возвращает окно на
место.

## 4. Разбиение по крейтам

### 4.1 `rst-core/src/mitosis.rs` (новый, платформенно-чистый)

```rust
pub const MAX_OFFSET_FRAC: f64 = 0.25;
pub const MIN_HALF_PX: i32 = 240;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SplitAxis { Vertical, Horizontal }
impl SplitAxis { pub fn flipped(self) -> Self; }

#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct PixRect { pub x: i32, pub y: i32, pub w: i32, pub h: i32 }

/// Доля разреза вдоль оси по позиции курсора, зажатая в
/// [0.5 - MAX_OFFSET_FRAC, 0.5 + MAX_OFFSET_FRAC].
/// Курсор вне прямоугольника — зажимается к ближайшей границе диапазона.
/// Вырожденный прямоугольник (w или h <= 0) — 0.5.
pub fn split_fraction(rect: PixRect, axis: SplitAxis, cursor_x: i32, cursor_y: i32) -> f64;

/// Две половины: `.0` — оригинал (левая/верхняя), `.1` — клон.
/// Сумма размеров половин по режущей оси РАВНА размеру исходного окна:
/// округление доли не должно терять пиксель.
pub fn split_rects(rect: PixRect, axis: SplitAxis, fraction: f64) -> (PixRect, PixRect);

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum MitosisRefusal {
    TooHeavy { bytes: u64, limit_bytes: u64 },
    NotEnoughMemory { bytes: u64, available_bytes: u64 },
    TooSmall { half_px: i32, min_px: i32 },
    NoExePath,
    SpawnFailed,
    NoSecondWindow,
}

/// Всё, что решается до единого Win32-вызова: размер половин и вес процесса.
/// `memory_bytes`/`available_bytes` — `None`, если замерить не удалось
/// (не повод отказывать: неизвестный вес пропускаем).
pub fn preflight(
    rect: PixRect,
    axis: SplitAxis,
    fraction: f64,
    memory_bytes: Option<u64>,
    limit_bytes: u64,
    available_bytes: Option<u64>,
) -> Result<(), MitosisRefusal>;
```

Тесты обязательны на: зажим доли с обеих сторон, курсор вне окна,
сохранение суммы ширин при round-trip, обе оси, каждый отказ `preflight`,
вырожденные прямоугольники.

### 4.2 `rst-win32/src/window_mitosis.rs` (новый)

```rust
/// Приватная (закоммиченная) память процесса, байты.
/// `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetProcessMemoryInfo`
/// → `PROCESS_MEMORY_COUNTERS_EX::PrivateUsage`. `None` — доступ закрыт.
pub fn process_private_bytes(pid: u32) -> Option<u64>;

/// Свободная физическая память системы, байты (`GlobalMemoryStatusEx`).
pub fn available_physical_bytes() -> Option<u64>;

/// Дескриптор запущенного второго экземпляра.
pub struct Sibling { pub pid: u32 }

/// Запустить второй экземпляр `exe_path`; рабочий каталог — каталог exe.
/// Дочерний процесс не должен умирать вместе с resticker и не должен
/// наследовать его консоль.
pub fn spawn_sibling(exe_path: &Path) -> Result<Sibling, Win32Error>;

/// ЧИСТАЯ функция отбора (тестируется без Win32): НОВОЕ окно этого
/// приложения в снимке. Совпадение — `hwnd` отсутствует в `known` И
/// (`pid == sibling_pid` ИЛИ `exe_path` совпадает без учёта регистра).
///
/// Ветка по exe обязательна: Проводник (и любое приложение с брокером)
/// открывает новое окно в УЖЕ ЖИВУЩЕМ процессе, а запущенный нами дочерний
/// процесс тут же выходит — по одному pid новое окно не найти никогда.
pub fn match_sibling_window<'a>(
    snapshot: &'a [WindowInfo],
    sibling_pid: u32,
    exe_path: &Path,
    known: &HashSet<usize>,
) -> Option<&'a WindowInfo>;

/// БЛОКИРУЮЩЕЕ ожидание нового окна: опрос `window_enum::enumerate()`
/// каждые `poll` до `timeout`, отбор — `match_sibling_window`.
/// Вызывать только с фонового потока (координатор блокировать нельзя).
pub fn wait_for_sibling_window(
    sibling_pid: u32,
    exe_path: &Path,
    known: &HashSet<usize>,
    poll: Duration,
    timeout: Duration,
) -> Option<WindowInfo>;
```

Рекомендованные значения вызывающего слоя: `poll = 150 ms`,
`timeout = 4 s` (изначально было 8 — сокращено по фидбэку: всё это время
окно стоит ужатым).

### 4.3 `resticker/src/mitosis_overlay.rs` (новый) — визуал резки

Чистый билдер примитивов, без Win32 и без состояния координатора:

```rust
/// Примитивы предпросмотра разреза в DIP-пространстве монитора.
/// `rect` — окно под курсором, `axis`/`fraction` — текущий разрез,
/// `blocked` — предпросмотр отказа (половина слишком мала): рисуется
/// красным.
pub fn split_preview(rect: DipRect, axis: SplitAxis, fraction: f64, blocked: bool) -> Vec<Primitive>;

/// Подсказка у курсора: «Esc — cancel».
pub fn cursor_hint(cursor_dip: (f64, f64), monitor_dip: (f64, f64)) -> Vec<Primitive>;
```

Композиция: рамка каждой половины (`WindowHighlight::primitives_custom`),
линия разреза `Primitive::Fill` толщиной 2 DIP, приглушённые полосы
запретных 25 % с каждого края режущей оси. Цвета — акцент проекта
`#3c9898`, отказ — красный `PIN_FLASH_COLOR_*`. Подсказка — `Primitive::Glass`
+ `Primitive::Text` тем же приёмом, что баннер (`BannerState`).

## 5. Инварианты

* Режим резки и режим редактирования — взаимоисключающие. Вход в один
  выключает другой.
* Пока режим резки активен, трекер окон принудительно разбужен (тот же
  приём, что для панели выбора окон).
* Свои окна (оверлеи, стикеры) резать нельзя — `window_pick::window_at`
  уже отсекает свой pid.
* Свёрнутое окно резать нельзя — `window_at` отсекает `iconic`.
* Ни один шаг не крадёт фокус: только `SW_SHOWNOACTIVATE`/`SWP_NOACTIVATE`.
