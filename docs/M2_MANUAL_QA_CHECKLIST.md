# M2 — ручной QA-чеклист режима редактирования

Статус: чеклист для человека. Срезы 1–6 (хоткей/затемнение/выделение/жесты/
undo/Ctrl+A/Delete/Ctrl+D, марка, диалог удаления, Ctrl+V, тулбар и панель у
курсора для одиночного выделения) уже связаны в координаторе
(`crates/resticker/src/overlay_manager.rs`) и должны работать сейчас.
Мультивыделение в тулбаре (`opacity: None`, батч-действия) и `BTN_SETTINGS`
панели у курсора — ещё нет.

Проверены только `cargo build`, юнит-тесты и запуск без падения — **жесты
мышью и клики по диалогу ни разу не кликались руками** (автоматизировать
глобальный хоткей из песочницы координатора не вышло, см. раздел 13),
поэтому этот лист — первая настоящая проверка поведения.

---

## 0. Окружение и как пользоваться

- Один монитор, масштаб 100% (смешанный DPI — M3). Разрешение лучше ≥1920×1080.
- Программа: `cargo run` из корня (или готовый бинарник). Трей — иконка resticker.
- Логи: `%LOCALAPPDATA%\resticker\logs\`. Конфиг: `%APPDATA%\resticker\config.json`.
- Перед прогоном: удалить `config.json` для чистого старта, добавить 2–3 PNG
  через «Настройки → Добавить стикер» (или подготовить файлы).
- Каждую строку отмечать ✔ / ✖, в «Комментарий» — что именно пошло не так
  (шаги воспроизведения, скриншот). Баг-репорт: логи + описание ожидаемого/фактического.

## 1. Вход/выход из режима редактирования

| # | Шаг | Ожидаем |
|---|---|---|
| 1.1 | Нажать `Ctrl+Alt+S` (хоткей из `config.json` → `hotkeys.edit_mode`, если задан) | Экран затемняется до ~50% чёрного; все видимые стикеры остаются поверх затемнения и полностью читаемы |
| 1.2 | Проверить, что фокус ушёл с активного приложения на оверлей | Клавиши `Ctrl+Z`/`Esc`/`Delete` теперь обрабатывает resticker, а не предыдущее окно |
| 1.3 | Нажать `Ctrl+Alt+S` ещё раз | Затемнение снимается, режим выключен; стикеры на месте |
| 1.4 | **Вне** режима: кликнуть по стикеру | Клик проходит насквозь (стикер некликабелен, реакция — у окна под ним) |
| 1.5 | В режиме: кликнуть по пустому тёмному месту | Выделение снимается (если было); рамка исчезает |
| 1.6 | Нажать `Esc` | Чистый выход из режима: затемнение снято, выделение сброшено, клики снова проходят насквозь |

Примечание: `Esc` во время незавершённого жеста обязан откатить жест к стартовой
позиции, а не закоммитить середину перетаскивания.

## 2. Выделение и рамка

| # | Шаг | Ожидаем |
|---|---|---|
| 2.1 | В режиме кликнуть по стикеру | Появляется белая рамка выделения **поверх** стикера + **8 белых квадратных ручек** (4 угла, 4 середины сторон); размер ручки ~10 DIP, толщина рамки ~2 DIP |
| 2.2 | Кликнуть по другому стикеру | Выделение переходит на него (старая рамка исчезает, появляется новая) |
| 2.3 | Кликнуть по пустому месту | Выделение снимается полностью |
| 2.4 | Навести курсор на разные зоны | Курсор меняется: тело — «переместить», ручки — ресайз-курсоры по направлению, кольцо за угловой ручкой — поворот (пока крестик — временная иконка), фон — стрелка |
| 2.5 | Зажать на пустом месте и потянуть (>4 DIP) | Появляется пунктирная рамка-марка с едва заметной заливкой; все стикеры, пересекшиеся с рамкой, выделяются вживую по ходу протяжки |
| 2.6 | Отпустить после протяжки марки | Марка исчезает, выделение остаётся тем, что показала протяжка |
| 2.7 | Зажать и отпустить на пустом месте **без** протяжки (<4 DIP) | Марка не появляется; ведёт себя как обычный клик по фону (2.3) |
| 2.8 | `Shift`+клик по невыделенному стикеру | Стикер добавляется к текущему выделению: рамки остаются у всех прежних + новая у кликнутого; перетаскивание не начинается |
| 2.9 | `Shift`+клик по уже выделенному стикеру | Стикер убирается из выделения (его рамка пропадает); рамки остальных на месте |
| 2.10 | Начать марку, выделить несколько стикеров, затем стянуть рамку обратно до размера **меньше 4×4 DIP** | Марка и выделение продолжают следовать за курсором (порог срабатывает только при старте марки); рамка не «замерзает» на последней надпороговой позиции. Отпустить — выделение соответствует итоговой рамке (может остаться пустым) |
| 2.11 | Начать протяжку марки и, **не отпуская** кнопку, нажать `Alt+Tab` (переключение окна — потеря захвата, `CaptureLost`) | Жест отменяется: марка-визуал исчезает, выделение возвращается к тому, что было **до** начала марки — никаких «зависших» рамок (как у остальных жестов) |

## 3. Перемещение и магнит

| # | Шаг | Ожидаем |
|---|---|---|
| 3.1 | Выделить стикер, зажать на теле, тащить | Стикер следует за курсором (за захват — точкой, где нажали, без «прыжка» центра) |
| 3.2 | Поднести край или центр стикера к краю/центру/углу монитора | Притягивается (магнит, порог по умолчанию 8 DIP) — см. «Известные ограничения» о расхождении со SPEC |
| 3.3 | Зажать `Ctrl` и вести стикер мимо края/центра | Магнит отключён — плавное движение без прилипания |
| 3.4 | Вытащить стикер почти за край экрана | Нельзя утащить так, чтобы с каждой стороны не осталось ~10% площади — стикер упирается |
| 3.5 | Отпустить | Стикер остаётся там, где отпустили; положение сохранено в конфиг |
| 3.6 | `Ctrl+Z` сразу после | Стикер вернулся на место до перетаскивания |

## 4. Ресайз за 8 ручек

Для каждой из 8 ручек (проверяем хотя бы по одной боковой и всем 4 углам —
углы покрывают оба варианта диагональных курсоров):

| # | Шаг | Ожидаем |
|---|---|---|
| 4.1 | Потянуть за боковую ручку | Стикер тянется только по этой оси; противоположная грань неподвижна |
| 4.2 | Потянуть за угловую ручку | Меняются обе оси; противоположный угол неподвижен |
| 4.3 | Угловая ручка + `Shift` | Пропорции сохранены (не искажается) |
| 4.4 | Угловая ручка + `Alt` | Масштаб от центра (стикер растёт/сжимается симметрично) |
| 4.5 | Ужать до минимума | Минимальный размер 16×16 DIP; дальше ручка «упирается» |
| 4.6 | Ресайз + `Ctrl+Z` | Возврат к размеру до жеста |
| 4.7 | Ресайз, не отпуская кнопку, нажать `Esc` | Выход из режима, стикер на стартовом размере (жест откатился) |

## 6. Undo / Redo

| # | Шаг | Ожидаем |
|---|---|---|
| 6.1 | Сделать подряд: переместить, ресайз, поворот | `Ctrl+Z` трижды — каждое действие отменяется по шагу; `Ctrl+Shift+Z` (или `Ctrl+Y`) трижды — возвращается |
| 6.2 | Клик по стикеру без движения, отпустить | Не тратит шаг истории (`Ctrl+Z` отменяет предыдущее реальное действие) |

| 6.4 | Выйти (`Esc`) и снова войти в режим | История сохраняется (в рамках сессии программы) |
| 6.5 | Перезапустить программу | История пуста (живёт только в памяти) — это по SPEC |

подписях могут рисоваться контурными квадратами — встроенный шрифт rst-render
пока содержит только цифры и символы (задача шрифта отдельно). Кнопка сброса
флага «не спрашивать» в настройках пока отсутствует.

## 13. Известные ограничения на момент прогона (не баги, не репортить)

- Порог магнита в коде — 8 DIP, SPEC 3.4 говорит 10. Расхождение известно
  (docs/M2_INTEGRATION_REVIEW.md, раздел 2).
- Смещение дубликата — +16 DIP, SPEC 3.6 говорит +20 px. Известно (там же).
- Шахматка `#FF00FF/#000000` для скрытых стикеров (SPEC 3.7) не реализована:
  скрытый стикер просто не рисуется.
- Иконка поворота — временный крестик (`.cur`-ресурс не добавлен).
- Диалог удаления и протяжка рамкой (марка) подключены и покрыты
  `cargo clippy`/`cargo fmt`/сборкой, но ни разу не кликались руками —
  автоматизировать глобальный хоткей (`Ctrl+Alt+S`) в песочнице координатора
  не получилось (SendKeys не пробивает системный `RegisterHotKey`), поэтому
  разделы 2 (клик по фону/протяжка) и 11 этого чеклиста — первая настоящая
  проверка их поведения.
- Мультивыделение: протяжка рамкой, `Ctrl+A` и `Shift`+клик (добавление/удаление
  по одному, раздел 2) подключены; мульти-драг ещё не реализован — `Shift`+клик
  не начинает перетаскивания.
- Конфликт хоткея редактирования с другим приложением (`Ctrl+Alt+S` уже занят)
  не показывается пользователю в UI: в лог (`%LOCALAPPDATA%\resticker\logs\`)
  пишется только `tracing::warn` «хоткей режима редактирования уже занят другим
  приложением». Полноценное уведомление (трей/диалог) — известное ограничение.
- Подписи тулбара-модала — английские; буквы могут рисоваться квадратами
  (см. секцию 11).
- Один монитор, масштаб 100% (M3 — мультимонитор и DPI).

## 14. Горячая клавиша «Показать/скрыть все стикеры»

Работает **вне и внутри** режима редактирования; семантика — сходимость к
однородному состоянию, как у «глаза» на тулбаре (`docs/M2_MULTISELECT_TOOLBAR_NOTES.md`,
раздел 3.2): есть хоть один скрытый → показать всех; все видимы → скрыть всех.

| # | Шаг | Ожидаем |
|---|---|---|
| 14.1 | Скрыть один стикер (в режиме, кнопкой «глаз»), выйти из режима, нажать `Ctrl+Alt+H` | Все стикеры показываются (сходимость: был скрытый — показать всех) |
| 14.2 | Нажать `Ctrl+Alt+H` ещё раз, когда все видимы | Все стикеры скрываются (вне режима они не рисуются) |
| 14.3 | Смешанное состояние: часть стикеров скрыта, часть видима | Одно нажатие показывает всех (группа «лечится» за один клик) |
| 14.4 | В режиме редактирования нажать `Ctrl+Alt+H`, затем `Ctrl+Z` | Показ/скрытие всех отменяется одним шагом истории |
| 14.5 | Проверить настройку: `config.json` → `hotkeys.toggle_all_stickers` (по умолчанию `Ctrl+Alt+H`) | Пустая/некорректная строка — хоткей просто не регистрируется (в отличие от `hotkeys.edit_mode`, фолбэка нет) |

Примечание: та же операция доступна кнопкой «Показать/скрыть все» в панели у курсора
(раздел 9.4) и «глазом» тулбара при мультивыделении — хоткей, кнопка панели и
тулбар должны сходиться к одному состоянию за один клик.

## 16. Митоз и группы окон (2026-09-09)

Требует двух окон одного приложения, умеющего открыть второй экземпляр
(Проводник — подходит), и собранной группы.

| № | Шаг | Ожидаемое |
|---|---|---|
| 16.1 | Собрать группу из двух окон, открыть её `Ctrl+Alt+<номер>` | Оба окна подняты и расставлены |
| 16.2 | Не закрывая группу, нажать `Ctrl+Alt+F` и разрезать одно из её окон | **Группа НЕ сворачивается** — остальные окна остаются на экране всё время: и пока целятся, и пока ждём второе окно |
| 16.3 | Дождаться появления второго окна | Оно встаёт во вторую половину; группа по-прежнему на экране |
| 16.4 | Закрыть группу хоткеем и открыть заново | Поднимаются ТРИ окна: второе окно митоза стало членом группы |
| 16.5 | Открыть менеджер групп | В составе группы на одного члена больше, имя нового члена — заголовок окна-ребёнка |
| 16.6 | Повторить митоз на группе из восьми окон | Разрез происходит, но девятым членом группа не растёт (нет раскладки на девять) |
| 16.7 | Прервать митоз `Esc` после прицеливания | Группа на месте, состав не изменился |
| 16.8 | Митоз приложения из `mitosis_single_instance_apps` (отказ по таймауту) | Оригинал вернулся в свой прежний размер, в группе записано его ПОЛНОЕ место, а не половина |

## 17. Отделение живого куска чужого окна (2026-09-10)

Для прогона нужен один разрешённый источник с видимым содержимым. Не
использовать окно самого resticker и не менять настройки denylist. Проверки
положения выполняются на мониторах с разным масштабом, если они доступны.

| № | Шаг | Ожидаемое |
|---|---|---|
| 17.1 | В окне-источнике нажать `Ctrl+Alt+C`, навести курсор на разрешённое окно | Экран затемняется как в режиме редактирования; у окна видна целая рамка и подсказка протяжки, окно под курсором выбирается с учётом верхнего z-порядка |
| 17.2 | Протянуть от верхнего левого к нижнему правому углу внутри окна и отпустить | Создаётся один живой стикер именно на месте выделения, а не в центре монитора; его источник — кусок выбранного окна |
| 17.3 | Повторить протяжку во все стороны (включая нижний левый и верхний правый угол) | Нормализованные границы дают тот же прямоугольник независимо от направления; сторонам меньше минимального размера отказ, стикер не создаётся |
| 17.4 | Начать выделение у края окна и протянуть за его пределы | Экранная область зажимается клиентской областью окна; итог не выходит за границы источника, доли crop остаются в диапазоне 0..1 |
| 17.5 | Отпустить протяжку ровно на границе окна; затем сделать случайный щелчок без протяжки | Граничное выделение создаёт корректный crop, случайный щелчок не создаёт стикер и не оставляет режим протяжки активным |
| 17.6 | Изменить содержимое окна-источника или дождаться его перерисовки | Живой стикер обновляет изображение; показывается та же семантическая область окна, а не застывший снимок |
| 17.7 | Оставить источник неподвижным на 3 секунды | Новые кадры без перерисовки не приходят и изображение не дёргается; измеренный результат — 0 кадров за 3 секунды |
| 17.8 | Свернуть окно-источник, затем восстановить его | Пока источник свёрнут, crop не получает кадров; после восстановления захват возобновляется. Сворачивание самого crop — отдельная операция |
| 17.9 | Закрыть источник, затем запустить то же окно снова с тем же exe, заголовком и классом | Crop скрывается и ждёт, а не удаляется и не показывает ошибку; после повторного запуска переподключается к подходящему окну |
| 17.10 | Навести курсор на crop и потянуть его за верхнюю полосу; проверить тело отдельно | Верхняя полоса и кнопки доступны только при наведении; drag полосы перемещает crop обычным transform, а область изображения остаётся неинтерактивной |
| 17.11 | Нажать кнопку сворачивания crop и затем иконку у ближайшего края монитора | Crop заменяется маленькой кнопкой у ближайшего края экрана; нажатие иконки возвращает crop на прежнее место и размер |
| 17.12 | Нажать кнопку закрытия crop | Crop удаляется вместе со своим сеансом захвата и записью стикера; другие стикеры и окно-источник не затрагиваются |
| 17.13 | Перезапустить resticker с ранее сохранённым crop, пока источник закрыт, затем запустить источник снова | Сохранённый crop остаётся в конфиге, после перезапуска прячется и ждёт окно, а после его появления переподключается |
| 17.14 | Повторить 17.2 на мониторах с масштабом 100% и 150%, включая монитор с отрицательной координатой `x=-1920` | Экранные пиксели протяжки превращаются в `CropRect` как доли клиентской области; место и размер нового стикера отдаются в `Placement` как DIP относительно выбранного монитора, без смещения из-за его глобального x |
| 17.15 | Кликнуть по телу живого crop (в том числе по тексту Chromium/Electron) | Событие не передаётся окну-источнику: crop не кликается; автоматизация через `SendInput` не используется, полоска и кнопки остаются единственными элементами управления |
| 17.16 | Создать новый crop и открыть поверх него другое окно | Crop уходит под открытое окно и не остаётся поверх всех окон по умолчанию |
| 17.17 | Навести курсор на crop и включить кнопку-булавку на его полосе | Crop остаётся поверх другого окна |
| 17.18 | Посмотреть на кнопку-булавку после включения | Булавка показывает включённое состояние |
| 17.19 | Выключить кнопку-булавку на полосе crop | Crop снова подчиняется обычному порядку окон |
| 17.20 | Перезапустить программу с включённой булавкой у crop | После запуска булавка остаётся включённой |
| 17.21 | Выключить булавку и перезапустить программу | После запуска булавка остаётся выключенной и сама не включается |
| 17.22 | Включить режим редактирования и потянуть crop за тело | Crop перемещается вслед за протяжкой |
| 17.23 | Открыть панель редактирования поверх обычного crop | Панель видна поверх окна crop |
| 17.24 | Включить булавку у crop и открыть панель редактирования | Панель остаётся видна поверх crop даже при включённом режиме «поверх всех окон» |
| 17.25 | Выйти из режима редактирования после перемещения crop | Окно crop возвращается на место, заданное его стикером |
| 17.26 | Навести курсор на crop после выхода из режима редактирования | Верхняя полоса снова находится непосредственно над окном crop |
| 17.27 | Проверить кнопку-булавку после выхода из режима редактирования | Состояние булавки совпадает с состоянием до входа в режим редактирования |

Точные контрольные значения захвата: статичное WGC-окно — 0 кадров за 3 секунды,
30 перерисовок — ровно 30 кадров; свёрнутый источник — 0 кадров до восстановления.
Проверка 17.14 фиксирует единицы контракта: `CropRect` — доли (0..1),
`screen_rect` — физические пиксели, а `Placement` — DIP своего монитора.
