# M4 — проектирование среза: вычисление окклюдеров (координаторная сторона)

Статус: **скоупинг, код не менялся** (docs only). Ветка `feat/m2-edit-mode`.
Основание: ADR-004/005/006, ARCHITECTURE.md §3.2–3.5, docs/M4_PREP_NOTES.md
§3.5–3.6, §4–6, docs/M4_WINDOW_TRACKER_DESIGN.md (трекер, готов),
docs/M4_WINDOWTRACKER_WIRING_REVIEW.md (сшивка 88507e8, ревью 1973d9b — без
багов). Прочитаны: `crates/resticker/src/overlay_manager.rs` (3924 строки —
текущее состояние: `OverlayMessage::Windows`, `mask_needed`, трекер в `run()`),
`crates/rst-win32/src/window_enum.rs` (`WindowInfo`/`WindowRect`),
`crates/rst-core/src/model.rs` (`VisibilityMode`/`OverlapRule`/`Settings`),
`DECISIONS.md` (ADR-004/005/006), `SPEC.md` §4 (слои видимости), §3.7
(шахматка скрытых).

Цель: конкретные решения для среза «окклюдеры» — координатор берёт снимок
окон от трекера (уже в канале), по правилам каждого стикера вычисляет, какие
окна его перекрывают, и отдаёт рендеру наборы прямоугольников для маски.
Рендер маски (`create_mask_texture`/`draw_mask`/правка PS, M4_PREP_NOTES §4) —
**отдельный** срез rst-render; здесь — контракт данных с ним. Панель выбора
окон — тоже отдельный срез (M4_WINDOW_TRACKER_DESIGN.md §8). Имена
функций/полей/строк — как в текущем коде; номера строк дрейфуют, имена нет.

## 0. Текущее состояние (что уже есть, не переизобретать)

- **Трекер готов** (`cc1c33b`): `WindowTracker` шлёт `WindowEvent::Changed(
  Vec<WindowInfo>)` полными снимками, дебаунс 16 мс, fast path по ADR-005
  (хуки только при `mask_needed`).
- **Сшивка готова** (`88507e8`): `OverlayMessage::Windows(TrackerWindowEvent)`
  в общем канале (FIFO с вводом), трекер стартует в `run()`
  (overlay_manager.rs:928–944), `mask_needed(&cfg)` пересчитывается раз за
  итерацию (overlay_manager.rs:1530–1536). Ветка `Windows(Changed)` пока
  только логирует (:1516–1525) — **первое действие этого среза — завести
  хранение снимка в этой ветке**.
- **Модель**: `VisibilityMode::{Always, Desktop, NeverOverlap,
  OverlapAllowlist}` + `rules: Vec<OverlapRule{process_name, title_pattern}>`
  (model.rs:259–292, 313–320); `Settings::never_overlap_taskbar`
  (model.rs:26). Расширение `OverlapRule` (`exe_path`/`match_kind`/
  `window_class`, M4_PREP_NOTES §6.2) **не сделано** — срез работает на
  текущей модели, срез-расширение модели подключается к той же функции
  матчинга без изменения вызовов (см. §2.3).
- **Окна**: `WindowInfo { hwnd, rect: WindowRect(x,y,w,h — физические px
  виртуального десктопа), pid, exe_path (полный путь, пустой при отказе
  OpenProcess), title, class, z_order, iconic, icon: None }`; `is_real_window`
  уже отсек оверлеи и не-реальные окна. `iconic == true` — свёрнутое окно,
  прямоугольник мусорный (не оклюдер, M4_PREP_NOTES §2.2).
- **Координатор**: `monitor_bounds: HashMap<MonitorId, MonitorBounds{id,
  bounds_px: Rect, scale}>` (overlay_manager.rs:894) — границы мониторов в
  физических px виртуального десктопа; `redraw()` рисует кадр на монитор,
  фильтруя стикеры по `placement.monitor_id` (overlay_manager.rs:3539–3544).
- **bin-крейт** имеет тест-модуль (overlay_manager.rs:3863), но конвенция
  крейта — чистая логика в rst-core (lib.rs: «вся логика покрывается
  юнит-тестами на любой ОС»): матчинг и геометрия — туда, сшивка — сюда.

## 1. Ключевое решение: пер-стикерные наборы окклюдеров с дедупликацией

M4_PREP_NOTES §4.2 предлагал **одну общую маску** = объединение окклюдеров
всех стикеров («маска общая на весь экран, а не на стикер»). Это некорректно
для пер-стикерных allow-list'ов: `VisibilityRule` — **у каждого стикера свой**
(SPEC §4.1). Если стикер A разрешает Chrome, а стикер B (режим «рабочий
стол») — нет, то в объединении Chrome присутствует (из-за B), и A
дискардится под Chrome — вопреки своему правилу. Объединение корректно
только когда у всех не-Always стикеров одинаковые правила.

**Решение:** маска **на стикер**, но текстуры дедуплицируются по набору
окклюдеров — в типичном случае (один-два разных набора правил) это одна-две
маски на монитор, что совпадает с «общей маской» по стоимости, а при
разных allow-list'ах — единственный способ соблюсти SPEC §4.1.

Контракт с рендер-срезом (§7): координатор отдаёт на монитор список
`OccluderSet { stickers: Vec<Uuid>, rects: Vec<WindowRect> }` — по одной
маске на **уникальный** набор прямоугольников; рендер рисует маску из
`rects` (скругление 8 px, R8-текстура — его зона) и биндит её к спрайтам
указанных стикеров. `Always`-стикеры ни в один набор не входят — им биндится
пустая маска (1×1 чёрная, уже предусмотрена M4_PREP_NOTES §4.3).

**Отклонение от M4_PREP_NOTES §4.2 зафиксировать** в M4_PREP_NOTES при
случае (одна строка: «маска на набор окклюдеров, а не на весь экран»).
ADR-004 при этом не нарушается — он говорит «из стикера вырезаются области
окон, которые по правилам должны быть выше», т.е. пер-стикерно по построению.

## 2. Чистый модуль `rst_core::occluders` (матчинг правил — туда)

Новый модуль в rst-core, без Win32-зависимостей: правило — платформенно-чистые
данные (`VisibilityMode`/`OverlapRule` — уже модель), кандидат-окно — тоже
чистый срез того, что нужно матчингу:

```rust
// crates/rst-core/src/occluders.rs (новый модуль)

/// Платформенно-чистое окно для матчинга правил. Координатор строит из
/// `rst_win32::window_enum::WindowInfo` (путь = `exe_path.to_string_lossy()`).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct OccluderCandidate {
    /// Полный путь к exe; `None` — OpenProcess не дал путь (защищённый
    /// процесс) — process-правила такому окну не соответствуют, окно
    /// считается оклюдером (консервативно).
    pub exe_path: Option<String>,
    pub title: String,
    /// Класс окна — для глобального правила «никогда не перекрывать
    /// панель задач» (SPEC §4.3: Shell_TrayWnd; единственное знание о
    /// Win32 в этом модуле — задокументированная строка-константа).
    pub class: String,
}

/// Окно оклюдер для стикера с правилами `(mode, rules)`?
/// `never_overlap_taskbar` — `Settings::never_overlap_taskbar`; при `true`
/// панель задач (класс `Shell_TrayWnd`) оклюдер всегда, даже если она в
/// allow-list стикера (SPEC §4.3: «панель задач — обычное окно и участвует
/// в списке», настройка делает её безусловной).
pub fn is_occluder(
    window: &OccluderCandidate,
    mode: VisibilityMode,
    rules: &[OverlapRule],
    never_overlap_taskbar: bool,
) -> bool {
    if never_overlap_taskbar && window.class == "Shell_TrayWnd" {
        return true;
    }
    match mode {
        // «Поверх всего» — оклюдеров нет вовсе.
        VisibilityMode::Always => false,
        // «Только рабочий стол» и «перекрытие любым окном» — одно и то же
        // для маски (M4_PREP_NOTES §6.1: свести их — открытый вопрос).
        VisibilityMode::Desktop | VisibilityMode::NeverOverlap => true,
        VisibilityMode::OverlapAllowlist => {
            !rules.iter().any(|r| rule_matches(r, window))
        }
    }
}

/// Одно правило цели: `process_name` И/ИЛИ `title_pattern`; пустое правило
/// (оба `None`) не матчит ничего — окно оклюдер (пустой allow-list =
/// «рабочий стол», M4_PREP_NOTES §6.3).
fn rule_matches(rule: &OverlapRule, window: &OccluderCandidate) -> bool {
    let by_path = match (&rule.process_name, &window.exe_path) {
        (Some(rule), Some(path)) => path_eq_ignore_case(rule, path),
        // exe_path неизвестен — process-правило не матчит (см. док кандидата).
        (Some(_), None) => false,
        (None, _) => false,
    };
    let by_title = match &rule.title_pattern {
        Some(pattern) => wildcard_match(pattern, &window.title),
        None => false,
    };
    by_path || by_title
}

/// `*`-подстановка (CONFIG.md, «Совпадение окон»): регистронезависимо.
pub fn wildcard_match(pattern: &str, text: &str) -> bool;

/// Пересечение двух прямоугольников; `None`, если не пересекаются.
/// Монитор-локальная геометрия маски (§4).
pub fn clip_rect(r: &Rect, bounds: &Rect) -> Option<Rect>;
```

### 2.1 Семантика матчинга `process_name`

`path_eq_ignore_case` — сравнение **по имени файла**, не по полному пути:
- полное совпадение `rule == exe_path` (регистронезависимо) — на случай,
  если будущие редакторы правил (M4_PREP_NOTES §6.2) станут писать полный
  путь;
- иначе `file_name(exe_path) == rule` — «chrome.exe» матчит
  `C:\...\chrome.exe`.

Поле модели называется `process_name` и CONFIG.md описывает его как имя
процесса — имя файла и есть семантика текущей модели; полный путь придёт с
расширением модели (§11), функция матчинга не меняется.

### 2.2 `wildcard_match`

Только `*` (CONFIG.md), произвольная позиция, несколько `*` подряд — один;
регистронезависимо. Классический рекурсивный/двух-указатель glob без `?`.
Отдельная маленькая функция — ей же воспользуется панель выбора окон
(фильтр списка) в будущем срезе.

### 2.3 Совместимость с будущим расширением модели (§6.2)

`match_kind`/`window_class`-правила придут новым полем в `OverlapRule` и
новым вариантом в `rule_matches` — сигнатуры `is_occluder`/`OccluderCandidate`
не меняются (class уже в кандидате).

## 3. Поток в координаторе: хранение снимка и кэш окклюдеров

### 3.1 Новые поля `run()`

```rust
/// Последний снимок окон от трекера (M4_WINDOW_TRACKER_DESIGN.md §6):
/// «эталон» для вычисления окклюдеров. Пуст, пока не пришёл первый
/// `Changed` (трекер шлёт его сразу после `set_mask_needed(true)`).
let mut window_snapshot: Vec<WindowInfo> = Vec::new();

/// Кэш окклюдеров: на монитор — наборы по уникальным наборам окон
/// (§1). Ключ — id монитора: геометрия окон локальна для монитора.
let mut occluder_cache: HashMap<MonitorId, Vec<OccluderSet>> = HashMap::new();
```

### 3.2 Ветка `Windows(Changed)` — вместо debug-лога (:1516–1525)

```rust
OverlayMessage::Windows(TrackerWindowEvent::Changed(windows)) => {
    window_snapshot = windows;
    // §3.5 M4_PREP_NOTES: пересчёт маски только если что-то реально
    // изменилось для стикеров — refresh_occlusion сравнивает с кэшем
    // и возвращает «изменилось ли».
    if refresh_occlusion(&cfg, &monitor_bounds, &window_snapshot, &mut occluder_cache) {
        need_redraw = true;
    }
}
```

### 3.3 Единый helper `refresh_occlusion` (пересчёт + гейт)

```rust
/// Пересчитать окклюдеры всех мониторов по текущему cfg/снимку окон.
/// Возвращает `true`, если хотя бы у одного монитора изменился набор —
/// вызывающий код решает, нужен ли redraw (M4_PREP_NOTES §3.5).
fn refresh_occlusion(
    cfg: &Config,
    monitor_bounds: &HashMap<MonitorId, MonitorBounds>,
    window_snapshot: &[WindowInfo],
    cache: &mut HashMap<MonitorId, Vec<OccluderSet>>,
) -> bool { ... }
```

Внутри, на каждый монитор из `monitor_bounds`:
1. взять `cfg.stickers` этого монитора (`placement.monitor_id == id`),
   **видимые** (`visible`, скрытые не рендерятся вне режима, в режиме маска
   выключена — §6) и не-Always (`mode != Always`);
2. для каждого такого стикера: `is_occluder`-фильтр по всем окнам снимка
   (`iconic` отбрасывать сразу — §4), геометрия через `clip_rect` (§4);
3. дедупликация: сгруппировать стикеры по одинаковому набору окклюдеров
   (хеш отсортированного списка hwnd) → `Vec<OccluderSet>`;
4. сравнить с `cache[id]` — при отличии записать и пометить «changed».

Стоимость: O(мониторы × стикеры × окна × правила) ≈ 3×30×25×2 — наносекунды;
на каждое сообщение цикла (включая MouseMove) пересчёт не делается — только
по `Windows`-событию и по изменению cfg (см. 3.4).

### 3.4 Пересчёт при изменении cfg (правила/режим стикера)

`mask_needed` уже пересчитывается раз за итерацию (:1530–1536); рядом —
тот же вызов `refresh_occlusion` (результат игнорируется — красный флаг
redraw уже выставил мутирующий обработчик; здесь только свежесть кэша):

```rust
if new_mask_needed != last_mask_needed { ... }   // существующий гейт
// Свежесть кэша окклюдеров: правила могли поменяться без смены режима
// (allow-list панели), и cache обязан догнать cfg до следующего redraw.
let _ = refresh_occlusion(&cfg, &monitor_bounds, &window_snapshot, &mut occluder_cache);
```

Сегодня ни один живой путь не меняет `VisibilityMode`/`rules` (ревью 1973d9b
отмечает статичность гейта) — вызов бесплатный, а когда панель появится,
ничего добавлять не придётся.

### 3.5 Порядок относительно остальных систем

- FIFO общего канала: `Windows`-событие не обгонит `MouseMove` — окклюдеры
  никогда не «опередят» ввод (гарантия сшивки, проверена в 1973d9b).
- Hot-plug (`MonitorsChanged`): `monitor_bounds` пересобран там же — новый
  монитор получит пустую запись кэша при первом `refresh_occlusion`; снятый
  монитор исчезнет из `monitor_bounds`, его запись кэша осиротеет — чистить
  не обязательно (никто не читает), но можно дропать в `teardown` из
  гигиены.
- Скрытие стикеров автоматом ADR-011 (`apply_loss_actions` → `visible =
  false`): скрытый стикер выпадает из окклюдеров (фильтр `visible` в шаге 1)
  и из кадра — согласованно.

## 4. Геометрия: виртуальный десктоп → локальные пиксели монитора

Маска живёт в физических px **своего** монитора (M4_PREP_NOTES §4.1), а
`WindowInfo.rect` — в px виртуального десктопа. Преобразование в
`refresh_occlusion`, на каждое окно-окклюдер:

```
локальный = clip_rect(rect, bounds_px монитора)
x' = rect.x - bounds_px.x,  y' = rect.y - bounds_px.y,
w'/h' — пересечение с [0, bounds_px.w]×[0, bounds_px.h]
```

- Окно, накрывающее два монитора, даёт по обрезанному прямоугольнику в
  набор каждого (если после клипа непусто).
- `clip_rect` возвращает `None` → окно на этот монитор не оклюдер (в т.ч.
  полностью за его границами).
- Свёрнутые окна (`iconic`) отбрасываются **до** геометрии: прямоугольник
  мусорный, маска не должна рисовать его по-живому (трекер их rect не
  обновляет — apply_location пропускает iconic, window_tracker.rs:389–398).
- DIP↔px: стикеры — DIP (placement), окклюдеры — px. Маска сэмплируется
  шейдером по `SV_Position` (физические px) — стикерной геометрии в
  координатах маски не нужно. Единственное место, где нужен пересчёт —
  отсечение полностью перекрытых (§5): AABB стикера (DIP) × scale → px.
  `scale` для монитора берётся из `monitor_bounds[id].scale`.

## 5. Отсечение полностью перекрытых стикеров (M4_PREP_NOTES §4.6)

В `redraw()` (overlay_manager.rs:3539–3544), для каждого видимого
не-Always стикера монитора, **до** добавления спрайта в кадр:

1. взять его набор окклюдеров из `occluder_cache` (по монитору и набору);
2. пересечь каждый окклюдер-прямоугольник (локальные px) с AABB стикера,
   переведённым в px (`hittest::aabb(placement, rotation)` × scale,
   сдвиг на origin монитора из `monitor_bounds` — AABB в DIP монитора, т.е.
   уже локальные координаты, домножаем только на scale);
3. объединить пересечения в bbox; если bbox покрывает AABB целиком —
   стикер невидим: спрайт в кадр не кладётся (PNG-случай; решение о
   декодировании видео — M5, ADR-004 «бесплатное отсечение»).

Консервативно (bbox × bbox — ложные срабатывания, когда оклюдеры образуют
«решётку») — приемлемо по M4_PREP_NOTES §4.6. `Always`-стикеры и режим
редактирования (§6) отсечению не подвергаются.

## 6. Режим редактирования: маска выключена

Во время `edit.active` маска не сэмплируется ни одним стикером (в кадр
биндится пустая маска): пользователь редактирует стикеры, и окклюзия —
симуляция «окно выше» — ему мешает; скрытые (`visible = false`) и так
показаны шахматкой (SPEC 3.7). Отсечение §5 тоже выключено в режиме.

Реализация: `redraw()` уже знает `edit.active`; при `edit.active` —
пропустить и маску, и отсечение (две проверки в одном месте, где строится
кадр). Состояние кэша при этом не трогается — выход из режима сразу
показывает правильную маску (кэш свежий, §3.4).

## 7. Контракт с рендер-срезом (что именно отдаёт координатор)

`OccluderSet` живёт в **rst-core** (рядом с модулем `occluders`): rst-render
зависит только от rst-core (не от rst-win32, Cargo.toml), а тип нужен обоим
— прямоугольники поэтому core-тип `Rect` (x/y — локальные px монитора,
могут быть отрицательными у мониторов левее начала виртуального десктопа
только ДО клипа; после клипа §4 — всегда ≥ 0), координатор конвертирует
`WindowRect` → `Rect` тривиально (те же поля):

```rust
// crates/rst-core/src/occluders.rs (или рядом в rst-render — решает срез
// рендера; контракт: тип виден обоим крейтам через rst-core)
/// Одна маска = один уникальный набор окон-окклюдеров монитора.
pub struct OccluderSet {
    /// Стикеры этого монитора, сэмплирующие эту маску.
    pub stickers: Vec<Uuid>,
    /// Прямоугольники в физических px монитора (локальные, после клипа §4),
    /// порядок не важен; скругление 8 px и заливка — на стороне рендера.
    pub rects: Vec<Rect>,
}
```

Поток: `redraw(монитор)` → `draw_mask(&occluder_cache[монитор])` →
спрайты стикеров биндят маску своего набора (рендер сопоставляет набор по
`stickers`), `Always`/edit-режим — пустую 1×1 чёрную. Что рендер делает с
наборами (одна R8-текстура, перерисовываемая на набор, или несколько —
память против draw-call'ов) — его срез; координатору нужно только
`Vec<OccluderSet>` на монитор. При пустом `rects` набор в кэш не кладётся
(маска не нужна).

**Согласование с рендер-срезом**: параллельная заметка
`docs/M4_MASK_RENDER_DESIGN.md` использует ту же пер-групповую семантику
(«группа» = этот `OccluderSet`; её `occluder_rects(монитор, группа, снимок,
правила, настройки)` = шаги 1–2 `refresh_occlusion`) и те же тестовые кейсы
(суффикс exe, подстрока title, регистр, пустые правила, iconic,
Shell_TrayWnd, клиппинг). Её API (`Device::draw_mask(rects: &[(f32×4)])`,
`draw_masked(masks: &[Option<&Texture>])`) не использует `OccluderSet` как
тип — координатор конвертирует `OccluderSet.rects` в плоские f32-кортежи и
сопоставляет стикер → индекс маски при сборке кадра. Противоречий нет;
термин «группа» и `OccluderSet` — одно и то же.

## 8. `never_overlap_taskbar` (SPEC §4.3, M4_PREP_NOTES §6.5)

`Settings::never_overlap_taskbar == true` → `Shell_TrayWnd` безусловный
окклюдер для всех не-Always стикеров, даже если в allow-list (SPEC §4.3:
переключатель «никогда не перекрывать панель задач»). Реализовано в
`is_occluder` (первая проверка, §2) — класс панели уже есть в кандидате;
настройка передаётся параметром из `cfg.settings`. Стикеры с `mode ==
Always` панель не перекрывает и без этой настройки (они поверх всего по
определению).

## 9. Тесты

- **rst-core::occluders** (юнит, без окон):
  - `wildcard_match`: таблица — точное, `*` в начале/середине/конце,
    несколько `*`, пустой паттерн/текст, регистр;
  - `is_occluder`: таблица по режимам (Always/Desktop/NeverOverlap/
    OverlapAllowlist), пустой allow-list (=Desktop), совпадение по
    имени файла и полному пути, `exe_path = None` (процесс-правило не
    матчит), `title_pattern`-wildcard, пустое правило (оба None), таскбар
    с выключенным/включенным флагом, таскбар в allow-list при флаге;
  - `clip_rect`: полное пересечение, частичное, касание границы, вне
    монитора (None), окно на двух мониторах.
- **Координатор** (bin, overlay_manager.rs:3863-тест-модуль или ручной
  smoke): снимок → кэш окклюдеров → отсечение — покрыть минимумом:
  `refresh_occlusion`-возврат «changed» при движении окна и no-op при
  неизменном снимке (синтетические `WindowInfo` без Win32 — поля-значения,
  никаких вызовов).
- **Ручные** (после рендер-среза): перетащи окно поверх стикера — маска
  следует с задержкой ≤16 мс; allow-list Chrome — стикер виден над Chrome,
  скрыт под остальными; два стикера с разными allow-list'ами — каждый
  подчиняется своему (проверка §1); «рабочий стол» — под любым окном;
  панель задач с включённой настройкой; минимизация окна убирает его из
  маски; режим редактирования показывает всё.

## 10. Порядок работ

1. **`rst_core::occluders`**: `wildcard_match`, `rule_matches`, `is_occluder`,
   `clip_rect` + юнит-тесты (§9). `pub mod occluders;` в lib.rs.
2. **Координатор — хранение**: `window_snapshot` в `run()`, ветка
   `Windows(Changed)` пишет снимок (пока без пересчёта).
3. **Координатор — кэш и гейт**: `OccluderSet`, `occluder_cache`,
   `refresh_occlusion` (маппинг `WindowInfo → OccluderCandidate`, фильтр
   iconic, геометрия §4, дедуп), вызов из ветки `Windows` и из
   per-итерационного места (:1530–1536); `need_redraw` по «changed».
4. **Отсечение §5** в `redraw()` + выключение маски в режиме (§6).
5. **`never_overlap_taskbar`** — параметр в вызов `is_occluder`.
6. Прогон: build/clippy/test (rst-core, rst-win32, bin) + ручной QA (§9)
   **после** подключения рендер-среза маски (шаги 1–5 сами по себе
   визуально ничего не меняют — окклюдеры считаются и кэшируются, но маску
   пока никто не рисует; порядок с рендер-срезом — на усмотрение
   координатора, стык по контракту §7).

## 11. Открытые вопросы

- **Расширение модели `OverlapRule`** (§6.2: `exe_path`/`match_kind`/
  `window_class`): текущий срез работает на `process_name` (имя файла) +
  `title_pattern`; расширение подключается в `rule_matches` без изменения
  остального (§2.3). Решить до панели выбора окон.
- **Разрешение/память маски** (R8 в размер монитора на набор — до 8 МБ на
  4K на набор; дедупликация §1 обычно держит 1–2): решение за
  рендер-срезом, при необходимости — даунскейл 1/2 с point-сэмплингом.
- **«NeverOverlap vs Desktop»** (M4_PREP_NOTES §9): для маски идентичны,
  свести в модели — отдельный маленький срез.
- **Ложные срабатывания отсечения §5** при «решётке» окклюдеров — принято
  (консервативность), точный per-pixel тест отложен до M5 (видео).
- **`z_order` окклюдерам не нужен** (ADR-004 §4.7) — наборы не сортируются;
  панель получит свой panel-режим трекера позже.
