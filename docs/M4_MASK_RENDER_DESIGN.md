# M4 — дизайн-заметка: рендер маски перекрытия

Статус: **проектирование, без изменений кода**. Основание: ROADMAP.md M4 («Рендер
маски перекрытия, скруглённые углы 8 px» и «Шейдер стикера с discard по маске»),
DECISIONS.md ADR-004 (маска в шейдере), ARCHITECTURE.md §3.2-§3.4,
`docs/M4_PREP_NOTES.md` §4-§5, `docs/M4_WINDOW_TRACKER_DESIGN.md` и уже сшитый
`WindowTracker` (cc1c33b + 88507e8: `OverlayMessage::Windows(Changed)`,
`mask_needed`-гейт). Прочитаны: `crates/rst-render/src/shader.rs` (`SPRITE_HLSL` —
один `mainPS` с t0/s0), `device.rs` (`Device::draw`), `sprite.rs` (`Sprite`),
`crates/rst-win32/src/window_enum.rs` (`WindowInfo`/`WindowRect` — физические px),
`crates/rst-core/src/model.rs` (`VisibilityRule`/`VisibilityMode`).

Цель заметки — зафиксировать решения для среза «маска»: топология маски (что чинит
неточность M4_PREP_NOTES §4.2), текстура и проход рендера, правка шейдера спрайта,
occluder-вычисление и стыковка с уже работающим `WindowTracker`. Реализацию пишет
координатор по этой карте.

---

## 1. Scope и исходное состояние

Срез закрывает два пункта ROADMAP: рендер маски (R8, скруглённые углы 8 px) и
шейдер стикера с `discard` по маске. Входы уже готовы:

- **Снимок окон** — `OverlayMessage::Windows(Changed(Vec<WindowInfo>))` (ветка
  1516-1525 сейчас логирует и отбрасывает снимок; этот срез даёт ему первого
  потребителя — снимок начинает храниться).
- **Гейт** — `mask_needed(cfg)` (1530-1536), fast path жив: хуки не стоят, пока все
  стикеры `Always`.
- **Модель** — `VisibilityRule { mode, rules: Vec<OverlapRule> }`,
  `OverlapRule { process_name, title_pattern }`; `WindowInfo` несёт `rect`
  (физические px), `exe_path`, `title`, `class`, `iconic`.
- **Рендер** — один PS (`mainPS` = `tex0.Sample(samp0, uv) * opacity`), один
  константный буфер `tr/misc/misc2` (в `tr` уже лежат центр/размер в физических px),
  `Device::draw(&self, target, sprites)` биндит t0/s0 по-спрайтно.

## 2. Топология маски: снять противоречие «общая vs по-стикерная»

M4_PREP_NOTES §4.2 говорит: «маска общая на весь экран — объединение оклюдеров
**всех** стикеров». Это верно **только когда у всех не-Always стикеров одно и то же
правило видимости** (типичный пресет: один allow-list на все стикеры). При
различающихся allow-list это неверно: стикер A прячется под Chrome, но не под
Photoshop; стикер B — наоборот. Объединение даст: A вырежется и под Photoshop
(потому что Photoshop в объединении из-за B) — нарушение allow-list A.

**Решение — маска по группам одинаковых правил.** Для каждого **различного**
«эффективного набора оклюдеров» рендерится своя R8-маска; спрайт биндит маску своей
группы.

- Ключ группы = правило видимости стикера (см. §6.1). В пресетах M4 это
  практически 1-3 группы: `Desktop` (окклюдеры = все окна) + по одной на каждый
  различный `OverlapAllowlist`. `Always`-стикеры маску не биндят (или биндят 1×1
  чёрную — шейдер один, §4.3).
- **Вырождение:** когда группа одна, это ровно «общая маска» из M4_PREP_NOTES §4.2 —
  дизайн совместим, просто формализован. Ошибка §4.2 — только в неявном допущении
  «группа одна».
- **Почему не «одна маска + вычитание allow-списка в шейдере»:** вариант
  `mask_all − mask_allowed` (две текстуры, вычитание в PS) корректен, но требует
  двух сэмплов и согласованного union-блендинга в двух масках — сложнее, чем
  per-group маска с одним сэмплом. При малом числе групп per-group проще.
- **Почему не per-sticker маска** (по одной на каждый стикер): 25 стикеров × 2 МБ
  (1920×1080 R8) ≈ 50 МБ + 25 проходов — оверкилл; группы решают ту же задачу.

**Следствие для API:** масок несколько (по группам), привязаны к монитору (§3).
Спрайт несёт ссылку на маску своей группы через параллельный срез, а не через поле
`Sprite` (тип `Sprite` — rst-core-тип публичного API, менять не надо, см. §5).

## 3. Текстура маски

- **Формат:** `R8_UNORM` (получить значение покрытия в красном канале; рендерится
  как offscreen render target, читается как SRV в t1). R8 рендер-таргет поддержан
  FL 11.0.
- **Размер:** физические пиксели **своего монитора** (один в один с backbuffer
  окна — тогда `SV_Position` в шейдере читает маску по совпадающим координатам, §4.4).
  Одна маска на (монитор, группу). Мультимонитор: у каждого `MonitorState` свой набор
  масок; снимок окон общий, oклюдеры клипятся/транслируются в координаты своего
  монитора (§6.4).
- **Владение и пересоздание:** маски — GPU-ресурсы на общем `Device` (M3 step 2),
  значит пересоздаются при `DEVICE_REMOVED` в `recover_device` (§7). Жизненный цикл
  на монитор: создать при старте/ресайзе окна (DpiChanged/geometry-change меняет
  размер → пересоздать R8 того же размера, что backbuffer).
- **Тип в rst-render:** новый `MaskTexture { texture, rtv, srv, width, height }`
  (или `MaskLayer`), создаётся `Device::create_mask(&(w, h)) -> Result<MaskTexture>`.
  Для fast path маска не создаётся — спрайты биндят существующую 1×1 чёрную
  `black_tex` (у неё `.r == 0`, `discard` не срабатывает; переиспользование без
  новой текстуры).

## 4. Проход рендера маски

Цель — залить в R8-маску объединение скруглённых прямоугольников оклюдеров с
1-px антиалиасингом краёв.

### 4.1 Геометрия и шейдеры

- **VS — существующий `mainVS` без изменений:** квад из 6 вершин, `tr.zw` = размер
  прямоугольника оклюдера в физических px, `tr.xy` = его центр, rotation = 0
  (`misc = (1, 0, 1, 1)`), flip ±1. Тот же константный буфер — тот же укладка
  `tr/misc/misc2`.
- **Новый PS `mainMaskPS`** — SDF скруглённого прямоугольника из `SV_Position` и
  `tr`:

  ```hlsl
  float4 mainMaskPS(VSOut i) : SV_Target {
      float2 center = tr.xy;
      float2 half = tr.zw * 0.5;
      float2 r = float2(8.0, 8.0);            // радиус углов, физические px
      float2 q = abs(i.pos.xy - center) - (half - r);
      float d = length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - r.x;
      float cov = 1.0 - smoothstep(0.0, 1.0, d);   // 1-px AA по SDF
      return float4(cov, 0, 0, cov);
  }
  ```

  Радиус 8 px — константа ADR-004 (компенсация углов Windows 11); при
  `half <= r` (узкий/низкий прямоугольник) SDF корректно деградирует к капсуле/линии.
- **Блендинг объединения:** отдельный blend-state `ONE, ONE, ADD` (красный канал);
  перекрывающиеся оклюдеры дают значение > 1 — порог `> 0.5` в шейдере спрайта это
  переваривает. (Альтернатива — `BLEND_OP_MAX`, требует FL 11.1 — не полагаемся.)

### 4.2 Порядок вызовов

`Device::draw_mask(&self, target_ctx_params, mask: &MaskTexture, rects: &[(f32 x4)])`:
clear маски в 0 → для каждого rect: set CB (tr), set VS+mainMaskPS+blend, `Draw(6,0)`.
Переиспользуется тот же цикл, что в `Device::draw` (Map CB → Draw). Масок мало
(группы), прямоугольников оклюдеров — десятки; проход дешевле одного спрайтового
кадра.

### 4.3 Один шейдер спрайта на оба случая

`SPRITE_HLSL` дополняется вторым слотом, `discard` **до** умножения на opacity
(преждевременный выход с ненулевой premultiplied-альфой недопустим — M4_PREP_NOTES
§4.3):

```hlsl
Texture2D maskTex : register(t1);
SamplerState maskSamp : register(s1);   // MIN_MAG_MIP_POINT, CLAMP
float4 mainPS(VSOut i) : SV_Target {
    if (maskTex.Sample(maskSamp, i.pos.xy).r > 0.5) discard;
    return tex0.Sample(samp0, i.uv) * i.opacity;
}
```

Fast path (нет групп / стикер Always) = биндим `black_tex` (`.r == 0`), отдельный
«голый» шейдер не нужен.

### 4.4 Совпадение координат: `SV_Position` ⇔ тексель маски

`SV_Position` в PS — центр пикселя выходного RT в его координатах (для
композиционной цепочки = клиентская область окна, физические px, origin top-left,
центры на +0.5). Маска — того же размера, что backbuffer, в тех же координатах:
сэмпл с `POINT/CLAMP` по `(x+0.5, y+0.5)` читает тексель `(x, y)` — 1:1. Тот же
проход маски рисовал оклюдеры в эти же координаты. **Инвариант: маска всегда того
же физического размера, что цепочка окна** — при DpiChanged/ресайзе пересоздавать
(§3). Стикер повёрнут/двигается — вырез стабилен, потому что маска сэмплится по
экранной позиции, а не по uv.

## 5. Стыковка с `Device::draw`

- Тип `Sprite` не меняется (его поля — rst-core-типы публичного API). Маска группы
  передаётся параллельным срезом:
  `Device::draw_masked(&self, target: &WindowTarget, sprites: &[Sprite], masks: &[Option<&Texture>])`
  — `masks[i]` в паре со `sprites[i]`, `None` = бинд `black_tex`. Внутри — текущий
  цикл `Device::draw` плюс `PSSetShaderResources(1, mask)` перед `Draw`.
- `draw_masked` отдельным методом (а не расширением `Sprite`) — M2/M3-вызовы
  (`draw`) не трогаются, как и предлагал M4_PREP_NOTES §5.
- Перед спрайтовым проходом: для каждой группы вызвать `Device::draw_mask`.
  `redraw_all` по мониторам: маски монитора пересчитываются только если снимок окон
  или правила изменились с прошлого кадра этого монитора (ADR-006: не на каждый
  кадр).

## 6. Occluder-вычисление (координатор)

### 6.1 Группировка стикеров

Ключ группы — «эффективный набор оклюдеров»:

- `Always` → не входит ни в одну группу (маска не нужна).
- `Desktop` → группа «все окна» (allow-list пуст — оклюдеры = все real-окна).
- `NeverOverlap` → по открытому вопросу M4_PREP_NOTES §9: в этом срезе приравнять к
  `Desktop` (обе семантики «прятаться под любым окном»), разницу уточнить по SPEC 7
  в модели до реализации.
- `OverlapAllowlist` → ключ = упорядоченный `rules` (нормализованный: отсортировать
  и сериализовать). Один и тот же список у нескольких стикеров = одна группа.

Число групп в реалистичном конфиге — 0..3; рост (стикер на стикер с уникальным
списком) ограничить нечем, но это осознанный выбор в пользу правильности (см. §2).

### 6.2 Матчинг окна против правил группы

Окно — оклюдер группы, если **не** совпадает ни с одним `OverlapRule` группы
(для `Desktop`/`NeverOverlap` правил нет — оклюдер всегда). Совпадение по
`OverlapRule`:

- `process_name` — суффиксное/регистронезависимое сравнение с `WindowInfo.exe_path`
  (полный путь в модели — M4_PREP_NOTES §6.2; короткое имя тоже считаем матчем для
  совместимости);
- `title_pattern` — совпадение подстроки с `WindowInfo.title` (регистронезависимо);
  оба поля `Option` — пустое правило не матчит ничего;
- сопоставление живёт в чистой функции `window_matches_rule(&WindowInfo, &OverlapRule) -> bool`
  — юнит-тестируется.

### 6.3 Фильтры перед рендером в маску

Пропустить: `iconic` (прямоугольник мусорный — не оклюдер), нулевые/неположительные
`w/h`, собственные окна resticker (трекер их уже отбраковывает по `WS_EX_NOACTIVATE`,
страхово повторить на стороне координатора не нужно). `never_overlap_taskbar`
(настройка) — `Shell_TrayWnd` добавляется **всегда** в оклюдеры любой группы
независимо от allow-list (M4_PREP_NOTES §6.5).

### 6.4 Мультимонитор: клиппинг и трансляция

Снимок окон глобальный (виртуальный десктоп), маска — на монитор. Для каждого
(монитор, группа): каждый прямоугольник оклюдера пересечь с `bounds_px` монитора
(`WindowRect` уже физические px виртуального десктопа — пересечение axis-aligned,
дёшево), трансляцию в локальные координаты монитора делает `(x − bounds_px.x,
y − bounds_px.y)`; пустое пересечение — пропустить. Это тот же класс геометрии, что
`monitor_rebind`/`redraw`-фильтр — пер-мониторная работа уже отработана в M3.

### 6.5 Триггеры пересчёта

Маска пересчитывается только когда меняется снимок окон или правила:

- `Windows(Changed(windows))` → **сохранить снимок** (`window_snapshot: Vec<WindowInfo>` —
  теперь есть потребитель), пересчитать группы и маски всех мониторов, `need_redraw = true`;
- изменение `cfg` (правила видимости, настройки) → пересчитать группы/маски;
- `mask_needed`-гейт уже пересчитывается раз за итерацию (88507e8) — при флипе в
  `false` маски можно освободить (снимок можно тоже дропнуть; вернётся с флипом в
  `true` по следующему `Changed`), при флипе в `true` — дождаться свежего снимка
  (или форсировать `set_mask_needed(false→true)` у трекера — он делает полный rebuild
  и эмитит `Changed`).

## 7. DEVICE_REMOVED и пересоздание

Маски — device-bound: в `recover_device` пересоздаются вместе с цепями (добавить
набор масок каждого `MonitorState` в список пересоздаваемого). CPU-часть (снимок
окон, группы, прямоугольники оклюдеров) переживает потерю устройства — после
восстановления достаточно перерисовать маски из сохранённого снимка (`need_redraw =
true` уже ставится recovery-путём). Трекер окон от D3D-потери не зависит (его кэш —
CPU) и продолжает эмитить `Changed` — свежесть снимка после восстановления
гарантирована ближайшим событием окон.

## 8. Отсечение полностью перекрытых стикеров

Консервативный прямоугольный тест (ROADMAP; точный попиксельный — только для
решения о декодировании видео в M5):

`fully_covered(aabb_стикера, occluder_rects) -> bool` — объединённый bbox
пересекающихся с AABB стикера прямоугольников оклюдеров его группы покрывает AABB
стикера. Чистая функция, юнит-тестируется. Покрытые стикеры пропускаются в
`redraw` (и позже не декодируются — `mute_invisible_stickers` уже в модели).
Вычисляется на пересчёт маски, не на кадр.

## 9. Тесты

- **HLSL-контракты** (по образцу `sprite_hlsl_contract`): `SPRITE_HLSL` содержит
  `mainMaskPS` (если в том же исходнике) или второй исходник `MASK_HLSL`; обе точки
  входа; `discard` стоит **до** `* i.opacity`; есть `register(t1)`/`register(s1)`.
  `sprite_shader_compiles_for_vs_and_ps` расширяется на маски-PS.
- **Чистые функции координатора** (без GPU): `window_matches_rule`,
  `group_stickers(cfg) -> Vec<Group>`, `occluder_rects(монитор, группа, снимок,
  правила, настройки) -> Vec<Rect>`, `fully_covered`. Табличные кейсы: суффикс exe,
  подстрока title, регистр, пустые правила, iconic/нулевой rect, Shell_TrayWnd,
  клиппинг за границы монитора.
- **GPU (`#[ignore]`, образец gpu_smoke):** создать маску, `draw_mask` двумя
  перекрывающимися прямоугольниками → прочитать R8 (CPU-копия backbuffer или
  staging) → значение > 0.5 в пересечении; `draw_masked` со спрайтом поверх маски →
  вырезанная область прозрачна.
- **Интеграционный (реальный десктоп, `#[ignore]`):** трекер + координатор-редрав —
  окно поверх стикера → стикер вырезан (визуально, ручная проверка).

## 10. Открытые вопросы

- **`NeverOverlap` vs `Desktop`** — свести к одному в модели или задокументировать
  разницу по SPEC 7 (M4_PREP_NOTES §9) до реализации группировки.
- **Радиус скругления 8 px** — константа в шейдере; не выносить в настройку, пока
  нет потребности.
- **Рост числа групп** — уникальный allow-list на каждый стикер = группа на стикер
  (память/проходы). Принять как осознанное следствие; при необходимости позже —
  layering-маски (несколько битовых слоёв в одной текстуре) — отдельная задача.
- **`SV_Position` при DPI-масштабе**: маска в физических px монитора — согласовано
  с backbuffer; пересоздание при DpiChanged обязательно (иначе рассогласование
  размеров и сдвиг выреза).
- **Окна нестандартной формы / тени DWM за extended bounds** — принятые артефакты
  ADR-004/§9, не блокеры.
- **Снимок хранится в `EditState` или отдельной локальной `run()`** — решить при
  реализации; не в `EditState` (это не состояние редактирования) — локальная
  переменная `run()` рядом с `monitor_bounds`/`ui_cache`.
