# resticker — конфигурация и хранение данных

## Расположение

```
%APPDATA%\resticker\
├─ config.json            — глобальные настройки + активные стикеры
├─ config.bak             — копия перед миграцией схемы и загрузкой пресета
├─ presets\
│  ├─ work.json
│  └─ stream.json
└─ pasted\
   └─ <uuid>.png          — материализованные вставки из буфера обмена

%LOCALAPPDATA%\resticker\
├─ cache\
│  └─ <hash>.bin          — даунскейленные версии больших изображений
└─ logs\
   └─ resticker-YYYY-MM-DD.log
```

Разделение осознанное: `%APPDATA%` перемещается вместе с профилем пользователя, `%LOCALAPPDATA%` — нет. Кэш и логи привязаны к конкретной машине и роумиться не должны.

---

## Правила записи

**Атомарность обязательна.** Конфиг никогда не перезаписывается на месте:

```
1. Записать в config.json.tmp в той же папке
2. FlushFileBuffers
3. MoveFileExW(tmp, config.json, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)
```

Выключение питания посреди обычной перезаписи оставило бы пользователя с обрезанным файлом и потерей всех настроек. Это не гипотетический риск, а типичный способ потерять доверие пользователя навсегда.

**Дебаунс.** Сохранение не происходит на каждое движение мыши. Пишем через 1 секунду после последнего изменения, а также принудительно при выходе из режима редактирования, при закрытии настроек и при завершении программы.

**Версионирование.** Поле `schema_version` присутствует с первой версии. Миграции — чистые функции `vN → vN+1`, применяемые последовательно. Перед миграцией создаётся `config.bak`.

**Битый конфиг.** Если файл не парсится: переименовать в `config.corrupt.<timestamp>.json`, попытаться загрузить `config.bak`, при неудаче — стартовать с дефолтов и сообщить пользователю в трее.

## Пояснения к полям

### `source.kind`

| Значение | Что хранится | Особенности |
|---|---|---|
| `file` | абсолютный путь | Файл не копируется. Пропал — стикер показывает заглушку, настройки сохраняются |
| `pasted` | путь внутри `%APPDATA%\resticker\pasted\` | Материализуется при вставке. Удаляется вместе со стикером |
| `window` | путь к exe + класс окна + паттерн заголовка | HWND в конфиг не пишется, он не переживает перезапуск |

### `visibility.mode`

- `all` — стикер поверх всего. Маска перекрытия не считается, это быстрый путь.
- `desktop_only` — эквивалентно `selective` с пустым списком: любое окно перекрывает стикер.
- `selective` — стикер виден над перечисленными целями и перекрывается всеми остальными окнами.

`targets[].match`:
- `process` — все окна процесса, включая те, что появятся позже
- `window` — конкретное окно, опознаваемое по классу и паттерну заголовка

`title_pattern` поддерживает `*` как подстановку. При нескольких совпадениях (три окна Chrome) под правило подпадают все.

### `placement`

Координаты — логические пиксели относительно левого верхнего угла **своего** монитора, а не глобального виртуального рабочего стола. `cx`/`cy` — центр, а не левый верхний угол: так поворот и масштабирование от центра выражаются естественно и не накапливают ошибку при многократных операциях.

### `settings.cursor_panel_offset`

Смещение центра панели у курсора относительно позиции курсора, DIP (SPEC 3.8 «Панель перетаскиваемая, её позиция запоминается»). `null` — дефолтное смещение (12, 12). Записывается координатором, когда пользователь перетащил панель; панель и так едет за курсором, поэтому хранится именно смещение, а не абсолютная позиция (оно не зависит от монитора).

### `origin`

Заполняется только когда стикер был вынужденно мигрирован с пропавшего монитора:

```jsonc
"origin": {
  "monitor_id": "\\\\?\\DISPLAY#DEL4321#...",
  "cx": 960.0, "cy": 540.0, "w": 512.0, "h": 384.0,
  "rotation": 0.0,
  "migrated_at": "2026-07-31T18:00:00Z"
}
```

Логика описана в [SPEC.md](SPEC.md) раздел 6.1 и [DECISIONS.md](DECISIONS.md) ADR-011.

### `order`

Целое число, определяющее порядок отрисовки: больше значит выше. При добавлении нового стикера ему присваивается `max(order) + 1`. Кнопки «выше»/«ниже» меняют местами значения с соседом. Периодическая нормализация к последовательности 0..N при сохранении.

### `tiling`

Секция тайлинга (M9, docs/TILING_DESIGN.md). Может отсутствовать целиком —
тогда она достраивается значениями по умолчанию тем же механизмом, что и
`presets` (crates/rst-core/src/config.rs:41), то есть старые конфиги читаются
без миграции.

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `enabled` | bool | `false` | Тайлинг включён. Выключен по умолчанию: включение — осознанный акт (SPEC 14.1). Переживает перезапуск |
| `own_alt_tab` | bool | `false` | Свой переключатель окон вместо системного Alt+Tab (SPEC 14.7). Выключен по умолчанию: при включении системный Alt+Tab перехватывается нашим хуком — это заметная подмена поведения, а не безобидная опция |
| `gaps_in` | int | `8` | Зазор между соседними плитками, px |
| `gaps_out` | int | `8` | Зазор до края рабочей области, px |
| `tab_bar_h` | int | `24` | Высота полосы табов у групп, px |
| `insert_policy` | string | `"dwindle"` | Куда встаёт новое окно: `"dwindle"` (делит сфокусированную плитку), `"master"` (мастер + стек), `"manual"` (соседом фокуса) |
| `rules` | array | `[]` | Правила окон, см. ниже. Пусто = тайлится всё |
| `bindings` | array | см. ниже | Горячие клавиши. **Пустой список = набор по умолчанию** (SPEC 14.4, `default_bindings`, crates/rst-core/src/config.rs:143), непустой — заменяет его целиком |
| `monitors` | array | `[]` | Мониторы, на которых тайлинг работает. Пусто = все |

#### `tiling.rules`

Правило — `{ "matcher": {...}, "action": ... }` (crates/rst-core/src/tiling/rules.rs).
Матчер проверяет окно по полям, **все заданные поля должны совпасть
одновременно** (И, а не ИЛИ — в отличие от правил перекрытия стикеров):

| Поле матчера | Семантика |
|---|---|
| `exe` | Имя файла процесса без учёта пути и регистра: `"firefox.exe"` матчит `C:\Program Files\Mozilla Firefox\firefox.exe` |
| `class` | Класс окна Win32, точное совпадение, регистрозависимо |
| `title` | Подстрока заголовка без учёта регистра; `*` работает как подстановка в начале и/или конце (`Chrome*`, `*Notepad`, `*YouTube*`) |

Действия:

| `action` | Смысл |
|---|---|
| `"float"` | Окно всегда плавающее, в раскладке не участвует |
| `"ignore"` | Окно полностью выключено из-под управления тайлинга. Терминальное: после совпавшего `ignore` остальные правила не смотрятся |
| `"tile"` | Вернуть окно в раскладку (перебивает более ранний `float`) |
| `{ "workspace": N }` | Окно появляется на воркспейсе N |

Правила применяются по порядку; последнее совпавшее выигрывает по своему
полю. `float`/`tile` не трогают воркспейс, назначенный более ранним правилом, —
плавающее окно всё равно принадлежит воркспейсу.

#### `tiling.bindings`

Запись — `{ "combo", "action", "arg", "submap" }` (crates/rst-core/src/config.rs:121):

| Поле | Тип | Смысл |
|---|---|---|
| `combo` | string | Комбинация в формате `HotkeyCombo::parse` (crates/rst-win32/src/hotkey.rs): `Alt+Shift+H`, `Left`, `Escape`, `NumPad0`, `F1`…`F24`; регистр не важен. Без модификатора — только для клавиш внутри модальных режимов |
| `action` | string | Действие, snake_case (полный список ниже) |
| `arg` | string \| null | Аргумент действия |
| `submap` | string \| null | Модальный режим, в котором бинд активен; `null` — глобальный бинд |

Действия и аргументы (crates/rst-core/src/tiling/action.rs):

| `action` | `arg` | Примечания |
|---|---|---|
| `focus_direction` | `left`/`right`/`up`/`down` (или `h`/`j`/`k`/`l`) | Обязателен |
| `move_direction` | то же | Переместить сфокусированное окно |
| `swap_direction` | то же | Поменять местами с соседом |
| `resize` | `right` или `right:0.1` | Шаг после `:` необязателен, без него — 5% контейнера |
| `toggle_split` | — | Ориентация контейнера горизонталь ↔ вертикаль |
| `toggle_group` | — | Группа с табами ↔ сплит |
| `cycle_group` | — / `next` / `prev` | Следующий/предыдущий таб |
| `toggle_floating` | — | Плавающий режим ↔ плитка |
| `toggle_fullscreen` | — | На весь воркспейс и обратно |
| `close_window` | — | Закрыть сфокусированное окно |
| `workspace` | номер ≥ 1 | Переключиться на воркспейс |
| `send_to_workspace` | номер ≥ 1 | Отправить окно на воркспейс |
| `enter_submap` | имя режима | Войти в модальный режим |
| `leave_submap` | — | Выйти из модального режима |

Ошибки в биндах не роняют конфиг: непонятная строка пропускается с
предупреждением в журнал, остальные бинды работают. Комбинации, которые
Windows не отдаёт (Win+…, `Ctrl+Alt+Del`, `Ctrl+Shift+Esc`), отбрасываются
(crates/resticker/src/tiling.rs:555).

#### Что означает пустой список

Умолчания живут ровно в одном месте — `TilingConfig::default()`
(`crates/rst-core/src/config.rs`). Отсутствующая секция `tiling` или
отсутствующее поле `bindings` достраиваются полной таблицей из SPEC 14.4.

Пустой список `"bindings": []` означает буквально то, что написано: биндов
нет, тайлинг управляется только мышью и пунктом трея. Это осознанный выбор,
а не способ «попросить умолчания».

## Формат пресета

Пресет — тот же формат, что и секция `stickers` в конфиге, плюс метаданные:

```jsonc
{
  "schema_version": 1,
  "name": "Стрим",
  "created_at": "2026-07-31T20:00:00Z",
  "app_version": "0.5.0",
  "stickers": [ /* ... тот же формат ... */ ]
}
```

Пресет **не содержит** глобальных настроек и хоткеев — только расстановку.

### Загрузка с недостающими элементами

```
1. Прочитать пресет, применить миграции схемы если нужно
2. Для каждого стикера проверить доступность источника:
     kind=file    → существует ли файл
     kind=window  → найдено ли подходящее окно среди запущенных
3. Если что-то недоступно — показать диалог со списком:
     • D:\refs\pose_01.png — файл не найден
     • OBS Studio — программа не запущена
   Кнопки: [Загрузить остальное] [Отмена]
4. При подтверждении применить пресет без недоступных элементов.
   Сам файл пресета НЕ изменяется.
5. Стикеры, чей монитор не найден, размещаются по правилам ADR-011.
```

### Экспорт и импорт

Пресет — обычный JSON, его можно передать другому человеку. При экспорте показывается предупреждение: внутри содержатся **абсолютные пути к файлам пользователя и имена запущенных программ**. На другой машине эти пути почти наверняка не совпадут.

## Ключ кэша даунскейла

```
hash = blake3(canonical_path || file_mtime || file_size || target_max_side)
```

Файл кэша содержит заголовок с исходными размерами, форматом и версией кодека даунскейла. Кэш можно удалить в любой момент — он пересоберётся. В настройках есть кнопка очистки и отображение занятого объёма.

## Миграции

```rust
fn migrate(mut value: Value) -> Result<Config> {
    let mut version = value["schema_version"].as_u64().unwrap_or(0);
    while version < CURRENT_SCHEMA_VERSION {
        value = match version {
            0 => migrate_v0_to_v1(value)?,
            1 => migrate_v1_to_v2(value)?,
            _ => bail!("неизвестная версия схемы: {version}"),
        };
        version += 1;
    }
    serde_json::from_value(value).context("не удалось разобрать конфиг после миграции")
}
```

Правила:
- Миграции только вперёд. Откат к старой версии программы не поддерживается.
- Перед первой миграцией сохраняется `config.bak`.
- Каждая миграция покрывается тестом на реальном файле конфига предыдущей версии, лежащем в `tests/fixtures/`.
