# resticker

> Приклей что угодно к своему монитору.

**resticker** — оверлей для Windows 11. Кладёт поверх рабочего стола картинки,
GIF, видео, куски чужих окон и сами окна — и при этом не мешает работать:
пока вы не включили режим редактирования, клики проходят сквозь стикеры.

<!-- СЮДА: главный скриншот рабочего стола со стикерами -->

**Статус:** 1.0.3, работает; инсталлятор не подписан сертификатом.
**Платформа:** Windows 11 x64. Windows 10 и другие ОС не поддерживаются.
**Язык интерфейса:** русский и английский, переключается в настройках.
**Лицензия:** MIT.

---

## Зачем это нужно

- Держать перед глазами шпаргалку, референс или чек-лист — поверх любого окна.
- Смотреть видео или стрим в углу экрана, не отдавая ему отдельное окно.
- Вынести кусок чужого окна — график, таймер, чат, индикатор — и видеть его
  всегда, не переключаясь.
- Держать нужное окно поверх остальных одним хоткеем.
- Собрать набор окон в группу и вызывать всю раскладку одной комбинацией.
- Разрезать окно пополам и получить рядом второй экземпляр того же приложения.

## Установка

1. Скачать `resticker_1.0.3_x64-setup.exe` со страницы релизов.
2. Запустить. Установка идёт в профиль пользователя, права администратора не
   нужны.
3. Windows SmartScreen предупредит о неизвестном издателе — у проекта пока нет
   сертификата подписи. «Подробнее» → «Выполнить в любом случае».

Нужен установленный WebView2 (в Windows 11 он есть из коробки) — на нём
работает окно настроек и меню трея. Сами стикеры рисуются не им, а Direct3D.

---

## Первый запуск

resticker живёт в трее и в оверлее, отдельного главного окна у него нет.

1. Открыть настройки: через меню трея (правый клик по иконке) или двойным
   кликом по иконке.
2. На вкладке «Стикеры» добавить файл — картинку, GIF или видео.
3. Стикер появится на экране. Чтобы его подвинуть, нажать `Ctrl+Alt+S` —
   это режим редактирования. Экран притухает, стикеры становятся
   интерактивными.
4. Выйти из режима той же комбинацией: стикер снова становится «сквозным»,
   клики уходят в окна под ним.

Если иконка трея отключена в настройках, в оверлей всё равно можно попасть
хоткеем режима редактирования.

## Хоткеи по умолчанию

| Комбинация | Что делает |
|---|---|
| `Ctrl+Alt+S` | режим редактирования (вход и выход) |
| `Ctrl+Alt+H` | показать или скрыть все стикеры |
| `Ctrl+Alt+M` | заглушить или вернуть звук стикеров |
| `Ctrl+Alt+T` | закрепить окно под курсором поверх всех |
| `Ctrl+Alt+U` | снять все закрепления |
| `Ctrl+Alt+G` | меню набора группы окон |
| `Ctrl+Alt+Shift+G` | удалить открытую группу |
| `Ctrl+Alt+Shift+T` | закрепить открытую группу поверх всех |
| `Ctrl+Alt+1` … `Ctrl+Alt+9` | показать группу окон с этим номером |
| `Ctrl+Alt+F` | разрезать окно надвое (митоз) |
| `Ctrl+Alt+C` | вырезать кусок окна |

Все комбинации переназначаются в настройках, вкладка «Управление»; новая
работает сразу, перезапуск не нужен. Хоткей режима редактирования обязателен,
остальные можно снять совсем. Если комбинацию уже занял кто-то другой,
программа скажет об этом прямо на экране.

## Что умеет

### Стикеры

- **Картинки:** PNG, JPG, WebP, BMP, GIF (первый кадр, если файл не анимирован).
- **Анимация:** GIF, APNG, анимированный WebP. Формат определяется по
  содержимому файла, а не по расширению.
- **Видео:** MP4, MKV, WebM, MOV, AVI, WMV, FLV, MPG, TS, M2TS, 3GP, OGV и
  другие — всё, что читает FFmpeg. Со звуком, с лупом, с полосой перемотки.
- **Видео с прозрачностью:** VP9 с альфой (WebM) и ProRes 4444.
- Аппаратный декод видео через D3D11VA, кадр не копируется через процессор.
- У каждого стикера своя прозрачность, поворот, отражение и порядок.

### Режим редактирования

- Выделение и трансформация: восемь ручек, поворот за угол, `Shift` —
  сохранить пропорции, `Alt` — тянуть от центра, `Shift` при повороте — шаг 15°.
- Несколько стикеров сразу: рамкой или `Shift`+клик.
- Магнит к краям и центрам мониторов.
- Отмена и возврат: `Ctrl+Z` и `Ctrl+Shift+Z`.
- Тулбар под выделением: прозрачность, слои видимости, скрыть, порядок,
  дублировать, удалить.
- Скрытый стикер виден чёрно-розовой шахматкой — как отсутствующая текстура
  в играх на Source.

### Слои видимости

Для каждого стикера отдельно:

- **Поверх всего** — виден всегда.
- **Только на рабочем столе** — прячется под любым окном.
- **Прятаться под любым окном, которое его перекрывает.**
- **Список разрешений** — прячется только под перечисленными окнами.
- **Список запретов** — виден поверх всех, кроме перечисленных.

Окна выбираются в панели «Слои видимости» — списком по процессам, с живым
обновлением: открыли новое окно, оно появилось в списке.

### Окна поверх всех

- `Ctrl+Alt+T` закрепляет окно под курсором, `Ctrl+Alt+U` снимает все
  закрепления.
- Закреплённые окна можно обводить рамкой (включается в настройках).
- Зазор в зоне привязки: при примагничивании окно ужимается на заданный
  процент, чтобы из-под него было видно стикер. Работает либо только для
  закреплённых окон, либо для всех — переключатель в меню трея.

### Группы окон

- `Ctrl+Alt+G` открывает меню набора: отмечаете окна, подтверждаете, группа
  получает номер.
- `Ctrl+Alt+<номер>` выносит всю группу на экран раскладкой, подобранной под
  число окон.
- Группу можно закрепить целиком (`Ctrl+Alt+Shift+T`) или удалить
  (`Ctrl+Alt+Shift+G`).
- Группы привязаны к сеансу загрузки: после перезагрузки компьютера они
  забываются, потому что тех окон уже нет.

### Кусок чужого окна

- `Ctrl+Alt+C` включает режим отделения: выбираете окно, протягиваете
  прямоугольник — и этот кусок живёт отдельно поверх экрана.
- Это живое зеркало: содержимое обновляется вместе с окном-источником.
- У куска своя полоса управления сверху — появляется по наведению, за неё же
  кусок перетаскивается; на полосе есть булавка «поверх всех окон».
- **По куску нельзя кликать.** Это зеркало пикселей, а не окно: мышь в него
  не попадает по устройству Windows. Управление — только через полосу.

### Митоз окон

`Ctrl+Alt+F` разрезает окно надвое: слева остаётся оригинал, справа
открывается второй экземпляр того же приложения. Ось выбирается сама по
положению курсора. Для приложений, которые не умеют второе окно, митоз
отключён списком.

### Пресеты

Вся расстановка стикеров сохраняется под именем и возвращается одним
нажатием — вкладка «Пресеты» в настройках и список в меню трея. Если файл
стикера из пресета пропал, программа скажет, какие именно элементы не
применились.

### Мультимонитор

- Стикер живёт в координатах своего монитора и переезжает между экранами
  перетаскиванием.
- Подключение, отключение и смена разрешения монитора обрабатываются на лету.
- Если монитор со стикерами отключили, стикеры временно переезжают на
  основной и возвращаются, когда монитор вернётся.

## Настройки

Вкладки: «Стикеры», «Пресеты», «Управление», «Общие», «Чёрный список».

Что стоит знать:

- **Автозапуск** и **тихий старт** — запускаться с Windows и стартовать сразу
  в трей.
- **Иконка в трее** — можно убрать совсем.
- **Скрывать от захвата экрана** — стикеры не попадут в скриншоты, OBS и
  демонстрацию экрана.
- **Не перекрывать панель задач.**
- **Ограничение частоты кадров на батарее** — экономит заряд ноутбука.
- **Глушить невидимые стикеры** — звук не играет, пока стикер скрыт или
  полностью перекрыт.
- **Чёрный список** — процессы и заголовки окон, которые программа не трогает
  вовсе (например, ваш видеоредактор).
- **Язык интерфейса** — русский или английский.

## Сколько ест

Замеры на машине разработки (2 монитора, 2560×1440 и 1920×1080, GTX):

| | |
|---|---|
| В покое, окна закрыты | около 62 МБ памяти, 0% процессора |
| Три анимации и видео на экране | около 96 МБ памяти, ~3% одного ядра |
| Процессов в диспетчере в покое | один |

Окна настроек и меню трея создаются только когда вы их открываете, и
уничтожаются, когда закрываете: пока они закрыты, WebView2 в памяти нет
вовсе. FFmpeg загружается в память только при первом видео.

## Чего программа не умеет

Это ограничения Windows, а не недоделки:

1. **Эксклюзивный полноэкранный режим.** Игра в exclusive fullscreen забирает
   вывод целиком, оверлей поверх неё не появится. Borderless fullscreen
   работает нормально.
2. **Окна с правами администратора.** Если окно запущено от админа, а
   resticker — нет, закрепить или разрезать его не выйдет: Windows блокирует.
3. **DRM-контент.** Поверх защищённого видео (например, Netflix в браузере)
   поведение оверлея непредсказуемо.
4. **Прозрачное видео декодируется процессором** — видеокарты не умеют
   альфа-канал.
5. **Кусок окна не кликается** — см. выше.
6. **Окно, свёрнутое в трей**, программа не видит и в группу не возьмёт.

## Как это устроено

Стикеры рисует не браузерный движок, а Direct3D 11 с DirectComposition —
одно нативное окно на монитор, сколько бы ни было стикеров. Tauri отвечает
только за окно настроек и меню трея. Куски чужих окон — настоящие окна, а не
спрайты оверлея.

Подробности: [ARCHITECTURE.md](ARCHITECTURE.md), решения и отвергнутые
альтернативы — [DECISIONS.md](DECISIONS.md), функциональная спецификация —
[SPEC.md](SPEC.md).

## Сборка из исходников

Нужно: Rust stable (MSVC), Visual Studio Build Tools 2022 с Windows 11 SDK,
Node.js 20+, FFmpeg 7.1 (LGPL shared build, только декодеры) и libclang.

Версия FFmpeg обязана быть именно 7.1 — под неё сгенерированы биндинги,
сборка с другой версией отклоняется.

```powershell
git clone https://github.com/<пользователь>/resticker
cd resticker
npm install

$env:FFMPEG_DIR = "путь\к\ffmpeg-7.1\install"
$env:LIBCLANG_PATH = "путь\к\llvm\bin"
$env:MINGW_RUNTIME_DIR = "путь\к\msys64\mingw64\bin"

# запуск без инсталлятора
cargo run -p resticker --release

# инсталлятор, результат в target\release\bundle\nsis\
npx tauri build --config crates/resticker/tauri.conf.json
```

Подробно — [CONTRIBUTING.md](CONTRIBUTING.md).

Код — MIT, см. [LICENSE](LICENSE).

FFmpeg подключается динамически как LGPL-2.1 shared build, собранный с
`--disable-gpl --disable-nonfree` (только декодеры); на код проекта это
требований GPL не накладывает. Бинарники FFmpeg распространяются со своей

Логика закрепления окон написана по мотивам модуля Always On Top из
[microsoft/PowerToys](https://github.com/microsoft/PowerToys) (MIT) —
самостоятельная реализация на Rust, а не копирование кода.

## Что проверить, прежде чем обещать

- **Смешанный DPI.** На машине разработки оба монитора 100%, поведение при
  125/150% вживую не проверялось. В старом README было написано «корректная
  работа со смешанным DPI» — это обещание не подкреплено.
- **Чистая машина.** Установка инсталлятором на компьютер без Visual Studio и
  без FFmpeg не проверялась — только запуск распакованного содержимого.
- **Форматы.** Список расширений видео взят из кода (диалог их принимает), но
  реально проверен только MP4 с H.264 и AAC. Остальные формально идут через
  FFmpeg, но живого прогона по каждому не было.
- **TIFF** в старом README упомянут, а в коде его нет — не переносить.
